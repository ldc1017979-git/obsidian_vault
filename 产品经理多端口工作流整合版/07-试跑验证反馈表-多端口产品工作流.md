## 7. 发现的问题

| 问题 | 严重程度 P0/P1/P2 | 原因 | 建议 |
|---|---|---|---|
| 查询对象锁定不够早，曾存在把表单截图误解为图片/附件查询的风险 | P1 | 查询类需求缺少“查询对象确认”专用门禁 | 新增“查询类需求对象确认卡”，未确认查询对象前不进入字段表和原型 |
| 目标截图出现后，旧 PRD 和旧原型未自动标注为早期版本 | P1 | 缺少交付物版本生效机制 | 项目目录增加“当前生效交付物说明”，页面结构变化后自动同步或标注旧版本 |
| “生产日期范围”和目标图单日期存在冲突，未第一时间登记为冲突项 | P1 | 对新输入与目标图冲突的敏感度不足 | 建立“冲突项登记表”，所有冲突进入 PRD 待确认和开发备注 |
| 总结文档初版偏页面还原总结，不是用户要的需求测试全过程总结 | P1 | 总结类文档类型识别不够细 | 写总结前先判断类型：页面差异、需求测试、能力提升、开发交付复盘 |
| 系统反推规范摘要不够标准化 | P2 | 使用截图反推时未完整按 09 清单形成独立摘要 | 使用现有系统截图时，输出“页面明确可见 / Codex 推断 / 缺口风险 / 需确认” |
| 多个交付物并行生成后，缺少统一口径同步 | P1 | 原型生成后没有强制跑同步清单 | 新增“原型生成后同步清单”：PRD、字段表、交互矩阵、开发备注、测试用例 |
| 权限继承规则后置 | P2 | 详情权限没有在查询结果设计阶段前置确认 | 跨表单查询默认拆分查询权限和详情权限，详情继承原表单权限 |
| QA 仍偏结构检查，真实业务结果验证不足 | P1 | 查询、重置、查看、无权限、返回路径等没有形成强制 QA 用例 | 查询类原型增加固定 QA 用例和 PASS / REVIEW / FAIL 判定 |
| 反推规范未覆盖足够多页面类型 | P2 | 本轮资料主要是目标页和追溯页截图 | 如果要做最终风格 HTML，应补列表、详情、表单、弹窗、权限状态样例；缺失时说明影响 |
| 敏感信息扫描需要前置 | P1 | 原型中曾出现测试账号字样 | 所有交付物生成后自动扫描真实链接、账号、密码、token、测试账号字样 |
