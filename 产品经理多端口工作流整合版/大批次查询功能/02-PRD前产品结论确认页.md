# 大批次查询功能 PRD 前产品结论确认页

## 1. 项目定位

项目名称：大批次查询功能。

端口/业务域：工厂端。

需求变化类型：现有系统新增模块。

系统承载关系：另一个工厂系统内建设。

核心目标：按批号聚合查询该批号关联的不同工序表单，并支持进入原工序表单只读详情页查看。

## 2. 业务目标

让生产现场人员、生产主管、工艺人员、质量人员等角色，能够通过批号快速查到该批次相关的工序表单记录，减少跨页面查找和人工确认成本。

## 3. 一期范围

一期包含：

- 一个列表查询页。
- 查询条件：批号、生产日期、班次、产线。
- 批号必填，生产日期/班次/产线选填。
- 支持手输、扫码、粘贴批号。
- 查询后展示查询条件摘要。
- 按工序生产顺序展示结果。
- 结果表展示工序表单原状态和关键字段摘要。
- 点击查看进入原工序表单只读详情页。
- 按权限过滤结果，无权限记录不展示。
- 查询不到记录时给出明确提示。
- 重置后清空查询条件，结果表回到空态。

## 4. 一期不做范围

一期不做：

- 导出。
- 统一状态映射。
- 缺失工序判断。
- 统一批次概览页。
- 原工序表单编辑。
- 最终 UI 风格 HTML 原型。

说明：

- 缺失工序判断需要标准工序清单和应生成表单规则，当前尚未确认。
- 最终 UI 风格需要目标工厂系统资料作为设计基线。

## 5. 用户角色

已确认：

- 生产现场人员可以使用。
- 多角色按权限控制数据范围。

暂定包含：

- 生产现场人员。
- 生产主管。
- 工艺人员。
- 质量人员。

权限原则：

- 用户只看到自己有权限访问的工序表单记录。
- 无权限记录不展示。

## 6. 核心对象

### 6.1 批号

用途：查询主条件。

规则：

- 必填。
- 不限制格式。
- 支持手输、扫码、粘贴。

### 6.2 工序表单记录

用途：查询结果中的核心行。

来源：

- 目标工厂系统已有工序表单清单。

示例：

- 拆包记录。
- 灌装封口记录。
- 打码记录。
- 热缩记录。

说明：

- 示例来自参考截图，不代表目标系统最终范围。
- 最终范围以目标工厂系统已有工序表单清单为准。

### 6.3 表单状态

用途：表示各工序表单当前状态。

规则：

- 一期展示各工序表单原状态。
- 一期不做统一状态映射。

### 6.4 关键字段摘要

用途：帮助用户在不进入详情的情况下判断记录是否为目标记录。

已确认展示列：

- 批号。
- 产线。
- 工序/表单名称。
- 原状态。
- 生产日期。
- 班次。
- 操作人。
- 提交时间。

## 7. 主流程

1. 用户进入大批次查询页。
2. 用户输入、扫码或粘贴批号。
3. 用户可选生产日期、班次、产线。
4. 用户点击查询。
5. 系统校验批号是否为空。
6. 系统按批号查询当前用户有权限访问的工序表单记录。
7. 系统展示查询条件摘要。
8. 系统按工序生产顺序展示结果表。
9. 用户点击某行“查看”。
10. 系统进入对应原工序表单只读详情页。

## 8. 页面结构

页面名称：大批次查询页。

页面组成：

- 查询区。
- 查询条件摘要。
- 结果表。
- 空态/异常提示区域。

查询区字段：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 批号 | 是 | 支持手输、扫码、粘贴；不限制格式 |
| 生产日期 | 否 | 辅助筛选 |
| 班次 | 否 | 辅助筛选 |
| 产线 | 否 | 辅助筛选 |

操作：

| 操作 | 规则 |
|---|---|
| 查询 | 按查询条件刷新结果表 |
| 重置 | 清空查询条件，结果表回到空态 |
| 查看 | 进入原工序表单只读详情页 |

结果表列：

| 列名 | 说明 |
|---|---|
| 批号 | 查询结果所属批号 |
| 产线 | 工序表单关联产线 |
| 工序/表单名称 | 工序或表单名称 |
| 原状态 | 工序表单自身状态 |
| 生产日期 | 工序表单关联生产日期 |
| 班次 | 工序表单关联班次 |
| 操作人 | 工序表单操作人 |
| 提交时间 | 工序表单提交时间 |
| 查看 | 进入原表单只读详情 |

## 10. 异常与空态

已确认：

- 查询不到记录：提示“未查询到该批号关联的工序表单，请检查批号是否正确”。

建议作为基础规则加入：

- 批号为空：提示“请输入批号”。

待研发补充：

- 查询接口失败提示。
- 详情页路由失败提示。
- 表单详情不存在提示。

## 11. 视觉基准与原型门禁

当前视觉基准状态：未确认。

原因：

- 模块承载在另一个工厂系统。
- 目标工厂系统截图、链接、录屏或设计规范尚未提供。

门禁结论：

- 可以继续整理 PRD 草稿。
- 可以继续整理业务结构稿和页面结构稿。
- 不能生成最终 UI 风格 HTML 原型。

进入最终 UI 风格 HTML 原型前，需要补充：

- 目标工厂系统截图、链接、录屏或设计规范。
- 目标系统菜单入口。
- 目标系统列表页、表单页、详情页样式参考。
- 目标系统权限和只读详情规则。
