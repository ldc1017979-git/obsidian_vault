# 数智工厂开发标注版原型 Skill

这个 skill 用来生成“可以交付给开发继续高保真实现”的标注版原型。

它不是普通注释工具，也不是把每个按钮、每个分页器、每个字段都机械说明一遍的说明器。它的目标是让研发一眼看懂：

1. 这个页面在业务上是干什么的
2. 页面内有哪些关键流程和状态
3. 哪些字段影响流程、权限、计算和状态变化
4. 哪些元素只是通用 UI，不值得单独标

## 使用顺序

遇到任务时，按下面顺序执行：

1. 先确认模块业务目标
2. 再拆业务对象和状态流转
3. 再判断页面属于列表、详情、新增、编辑、审批、确认、配置还是台账
4. 再决定页面上哪些区域需要标注
5. 最后再补字段级标注和 QA 校验

不要反过来从字段开始标。

## 先读什么

如果当前工作区里存在下面文件，优先读取：

- `数智工厂系统信息架构与原型生成准则.md`
- `数智工厂系统设计风格与交互规范基线.md`
- `工厂端原型生成检查清单.md`
- `系统菜单可见结构总览.md`
- `动作权限与隐藏路由字典.md`
- 当前模块的 PRD
- 当前模块的开发标注版 HTML
- `15-开发备注上下文工具设计规范.md`
- `16-PRD质量检查与评审门禁.md`
- `18-需求变更与影响回归记录.md`（发生变更时）

读取`references/workspace-sync.md`只用于确认候选文件位置。复测项目不得读取任何由第一轮案例结论生成的专用业务规则；业务规则必须从本轮原始资料、产品确认和当前有效PRD重新建立。

## 自动刷新工作区参考

这个 skill 的完整版不是只依赖静态规则。

每次真正开始生成或更新“开发标注版原型”前，都要先做一次工作区同步，把当前工作区里最新的 PRD、业务逻辑标注版 HTML、复盘报告和系统基线文件整理成最新快照，再按快照工作。

### 执行方式

如果可以访问当前项目工作区，先运行：

```bash
python3 scripts/sync_workspace_reference.py "<当前工作区根目录>"
```

例如在积分模块场景下，可传入当前模块所在根目录。脚本会自动：

- 查找最新 PRD
- 查找最新业务逻辑标注版 HTML
- 查找最新复盘/能力提升报告
- 记录当前系统基线文件
- 生成 `references/workspace-sync.md`

### 使用规则

同步完成后，必须先读：

1. 当前项目原始业务资料和当前有效PRD
2. `references/workspace-sync.md`

其中`workspace-sync.md`只负责反映候选PRD、原型和基线位置，不提供业务答案。

如果两者有冲突，按下面顺序判断：

1. 先检查是不是工作区最新文件已经明确推翻旧规则
2. 如果是，则以 `workspace-sync.md` 中的最新约束为准
3. 如果只是表达差异、不是规则变更，则列为待产品确认，不能擅自选取

同步快照只是“候选文件索引”，不是事实来源。必须检查当前有效版本、废弃标记和11号版本同步清单；不能仅按修改时间认定最新有效版本。找不到唯一有效PRD/HTML时停止正式交付并列出冲突。

### 更新后回写

如果本次任务已经修改了：

- PRD
- 开发标注版 HTML
- 问题复盘/规则沉淀文档

那么在交付前要再运行一次同步脚本，刷新 `references/workspace-sync.md`。

这样下次再次调用本 skill 时，读取到的就是最新口径，而不是上一次改动前的快照。

## 核心原则

### 1. 先业务，后字段

标注顺序必须是：

`页面业务目的 -> 页面流程/状态 -> 关键动作 -> 关键字段 -> 异常/权限规则`

不要上来就把每个输入框都解释一遍。

### 2. 不为标记而标记

以下内容默认不单独编号、不单独解释，除非它们真的改变业务结果：

- 分页数字按钮
- 单纯上一页/下一页
- 普通刷新图标
- 普通表格排序图标
- 纯展示型标签页壳子
- 没有业务差异的重复操作按钮

如果一个控件只影响浏览体验、不改变业务状态，就不应该抢占标注注意力。

### 3. 页面标注必须先讲“这页在干什么”

每个页面至少要先有一段页面级标注，说明：

- 页面面向谁
- 页面承接哪个业务环节
- 页面输入什么
- 页面输出什么
- 页面完成后状态会怎么变

如果没有这一层，只做字段说明，原型会很僵硬。

### 4. 标注只覆盖关键实现点

优先标这些：

- 状态流转
- 审批逻辑
- 员工确认逻辑
- 申诉/驳回/重提
- 自动带出和联动
- 禁用/只读/置灰
- 权限入口
- 配置项如何影响业务页
- 列表状态与操作按钮的对应关系

### 5. 不把演示便利做成正式逻辑

严禁为了原型演示方便，加入正式系统中不应存在的交互，例如：

- 管理视图/员工视图手动切换器
- 为了看页面方便临时造出来的入口按钮
- 只弹 toast、不进入真实页面或弹窗的假交互
- 不符合正式权限模型的跨角色切换

这种内容即使存在，也必须在开发交付前移除。

### 6. 新增、编辑、详情必须严格区分

必须明确区分：

- 新增态：默认空白或占位
- 编辑态：带回填值
- 详情态：只读
- 草稿态：可继续编辑，但入口和标题要明确

不要把新增页做成默认回填历史数据的样子。

### 7. 可点击元素必须有真实结果

所有看起来能点的元素，都必须至少属于以下一种：

- 打开新页面
- 打开弹窗/抽屉
- 切换区域内容
- 执行状态变更
- 执行二次确认
- 执行搜索/重置/导出

如果只是 toast 占位，不能算完成。

### 8. 开发交付原型必须保证前后一致

同一个业务对象的以下页面，规则要一致：

- 列表页
- 详情页
- 新增页
- 编辑页
- 审批页
- 配置页
- 台账页

如果工作区里已经有 PRD 更新、问题复盘更新、HTML 更新，页面一致性检查必须按最新同步快照重新执行一遍，不能只看历史版本。

例如字段名称、状态名称、操作按钮文案、审批节点表达，不能前后打架。

## 页面标注层级

生成标注时，优先按四层组织：

### 第一层：页面级标注

说明页面的业务职责。

示例：

- 该页用于管理员处理积分申请单，核心是查询、审批、跟踪状态
- 该页用于员工发起积分申请，提交后进入审批或待确认链路
- 该页用于配置积分类型，配置结果将反向影响申请页的可选项和分值标准

### 第二层：流程级标注

说明页面内的关键流程段。

例如：

- 查询区
- 列表处理区
- 审批动作区
- 配置维护区
- 台账追溯区

### 第三层：关键字段级标注

只标这些字段：

- 会触发联动
- 会影响校验
- 会影响权限
- 会改变状态
- 会影响计算
- 会影响后续页面显示

普通备注、普通非关键展示字段可以不单独标。

### 第四层：状态和动作标注

必须讲清：

- 哪些状态下显示哪些按钮
- 哪些状态下只可查看
- 哪些动作会进入审批
- 哪些动作需要员工确认
- 哪些动作会生成台账

## 上下文工具交互合同

标注必须嵌在真实业务页面旁，不能做成空白页上的长文本。

- 页面元素悬停/聚焦时显示标注入口；点击编号后打开右侧抽屉并定位对应规则。
- 抽屉默认只显示当前页面相关内容，可切换页面、字段、动作、状态、权限、数据/API、异常、待确认。
- 支持按编号、页面名、字段名、按钮名和规则关键词搜索。
- 标注项必须包含：编号、适用页面/状态/角色、来源文档与章节、实现要求、验收结果、待确认状态。
- 从标注项可反向高亮或滚动到页面元素；关闭抽屉后焦点回到触发元素。
- 抽屉不遮断主流程；桌面端打开后页面仍可操作，窄屏使用全屏层并可明确返回。
- PRD是正式依据；标注只做开发走读辅助。规则冲突必须展示冲突来源，禁止静默选择。

编号建议：页面`Pxx`、字段`Fxx`、动作`Axx`、状态`Sxx`、规则`Rxx`、异常`Exx`。编号必须与PRD/交互矩阵/测试记录一致。

## 数智工厂开发标注输出要求

如果用户要“业务逻辑标注版原型”，输出必须至少包含：

1. 页面级业务说明
2. 页面分区逻辑说明
3. 关键字段逻辑说明
4. 状态流转说明
5. 与配置页、审批页、台账页的关联说明

不要只给字段字典。

## 标注文风要求

标注必须像产品经理给研发的实现说明，不要像培训教材。

推荐写法：

- “该字段由积分类型自动带出，员工不可手输”
- “提交后单据进入待审批；若当前类型无需审批，则直接进入待员工确认”
- “该区域不单独做顶部导航入口，而是由列表页行操作进入”

不推荐写法：

- “这是一个输入框”
- “点击后执行当前页面定义的业务动作”
- “用于展示某某信息”

## QA 检查清单

交付前至少检查：

### 结构检查

- 页面入口是否真实
- 是否误放了流转型页面到左侧主菜单
- 是否存在 demo 型角色切换器

### 交互检查

- 所有可点击元素是否真有结果
- 所有标签页是否都可切换
- 所有新增/编辑/审批按钮是否进入真实表单
- 弹窗是否可关闭

### 业务检查

- 新增/编辑/详情状态是否混淆
- 配置项是否真的影响业务页
- 列表状态和操作按钮是否一致
- 审批状态和详情页状态是否一致

### 显示检查

- 短字段不强制换行
- 置灰字段不能像可编辑字段
- 只读字段不能看起来还能操作
- 表格多列场景优先内部横向滚动

### 标注工具检查

- 任取一个字段、一个按钮、一个状态，开发是否能在30秒内找到来源、实现要求和验收标准
- 页面元素到标注、标注到页面元素是否双向定位
- 页面切换、搜索、分组、关闭、焦点恢复是否真实可用
- 标注内容是否与当前有效PRD、规则表、交互矩阵一致
- 是否按`14-HTML原型完整测试验收SOP.md`逐个测试所有标注入口和工具按钮

## 禁止项

出现以下情况，必须主动纠正：

- 标注数量远大于真正的业务信息量
- 连分页按钮都逐个编号
- 页面没讲业务，只在解释字段
- 为了好看擅自改业务逻辑
- 页面看起来能点，实际上只有提示
- 配置页和业务页的字段命名不一致
- 新增页带历史数据


开始前执行工作区同步并读取`references/workspace-sync.md`，只用于定位本轮当前有效文件。不得从Skill内置内容推导项目业务答案。

## 交付格式

完成后，默认输出：

1. 原型文件路径
2. 本次采用的标注规则摘要
3. QA 检查结果
4. 未通过/待修复项

如果用户要求同时沉淀规则，还应补充：

5. 本次新增或更新的 skill 路径
6. 本次同步生成的 `workspace-sync.md` 路径
