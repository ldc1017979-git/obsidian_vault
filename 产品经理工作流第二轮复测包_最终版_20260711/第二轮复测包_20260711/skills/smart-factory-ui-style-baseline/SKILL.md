# 数智工厂系统 UI 风格基线 Skill

这个 skill 负责把“数智工厂系统目前已经确认的整体界面基准风格”固定下来，供后续新模块生成、旧模块改造、原型补全和页面统一时复用。

它不是业务逻辑 skill，也不是单页面美化器。

它解决的是下面这些问题：

1. 后续页面是否还保持同一套后台外壳
2. 新模块是否还像同一个系统里长出来的页面
3. 列表、详情、新增、配置、看板这些页面类型是否继续遵守统一骨架
4. 是否会把系统做成营销页、卡片流、深色大屏、演示型页面

## 使用场景

出现以下任务时，必须优先使用本 skill：

- 新增系统模块页面
- 旧页面重做视觉与结构
- 从业务需求生成数智工厂原型
- 要求“按当前系统风格对齐”
- 要求“后续风格统一，不要跑偏”
- 要求“和现有系统 UI 一致”

如果任务还同时涉及“开发交付型业务逻辑标注”，请和 `smart-factory-dev-annotated-prototype` 一起使用：

1. 先用本 skill 冻结系统 UI 基线
2. 再用标注 skill 处理业务逻辑、状态和开发说明

## 先读什么

若当前工作区存在以下文件，优先读取：

- `数智工厂系统设计风格与交互规范基线.md`
- `数智工厂系统信息架构与原型生成准则.md`
- `工厂端原型生成检查清单.md`
- `系统菜单可见结构总览.md`
- `动作权限与隐藏路由字典.md`

同时读取：

- `references/system-ui-style-rules.md`
- `references/workspace-ui-baseline-sync.md`

## 自动同步工作区 UI 基线

在真正开始生成页面前，先运行：

```bash
python3 scripts/sync_workspace_ui_baseline.py "<当前工作区根目录>"
```

脚本会自动：

- 查找最新系统风格基线文档
- 查找最新信息架构准则
- 查找最新检查清单
- 记录当前工作区相关 HTML 样本
- 生成 `references/workspace-ui-baseline-sync.md`

同步结果只是候选来源索引。必须确认当前有效版本，并实际读取代表性截图、HTML/CSS或规范正文；不能把“文件较新”当作“基线已确认”。

如果本次任务修改了基线文档、HTML 样本或相关规则，交付前要再跑一次同步脚本回写最新快照。

## 核心原则

### 1. 先系统壳，后页面内容

任何新页面都先判断是否应继承：

- 左侧菜单
- 顶部业务域导航
- Tags-View
- 浅灰页面背景
- 白色内容容器

不要先画页面内容，再临时套一层外壳。

### 2. 先页面类型，后字段布局

先判断页面属于哪类：

- 工作台 / 门户
- 标准列表页
- 单据新建 / 编辑页
- 详情页
- 记录 / 检查表页
- 报表 / 统计页
- 基础资料 / 配置页
- 流程审批页
- 数据看板页
- 知识 / 文件页

只有先判定页面类型，后续布局才不会跑偏。

### 3. 保持“工厂业务后台工具感”

该系统是：

- 中高密度业务后台
- 表格、表单、详情、审批、台账驱动
- 多业务域、多页签、多状态流转

不是：

- landing page
- 营销页
- 作品集
- 插画化 SaaS 首页
- 深色科技大屏

### 4. 组件语义优先复用 Element Plus 风格

后续原型默认按 Element Plus 语义生成：

- `el-button`
- `el-input`
- `el-select`
- `el-date-picker`
- `el-table`
- `el-tabs`
- `el-pagination`
- `el-dialog`
- `el-drawer`
- `el-upload`

不要重新发明一套明显不属于这个系统的控件。

### 5. 颜色语义以证据为准

以下仅作为当前候选默认值，必须先与截图、CSS变量和已确认规范核对：

- 蓝：主流程、查询、确认、导航激活
- 绿：新增、添加、创建
- 黄：编辑、提示、警示
- 红：删除、作废、异常、错误
- 灰白：取消、重置、普通辅助动作

### 6. 表格优先于卡片流

该系统核心承载是表格，不是卡片流。

所以：

- 列表页优先表格
- 详情页优先信息表 + 明细表
- 配置页优先配置表
- 报表页优先查询 + 表格 + 导出

不要把标准后台页改造成卡片流列表。

### 7. 复杂业务优先独立路由，不塞小弹窗

复杂新建、详情、编辑、审批应优先使用独立页签页。

弹窗/抽屉只适合：

- 轻量确认
- 辅助选择
- 简单配置
- 批量选择

### 8. 看板页也保留后台壳

即便是数据看板，默认也要保留：

- 左侧菜单
- 顶部导航
- Tags-View

并保持白底、浅灰底、清爽图表风。

除非用户明确要求“大屏驾驶舱”，否则不要自动切到黑蓝全屏大屏风格。

## 系统硬基线

只有被截图/CSS/规范和产品确认支持的项目才能标记“硬基线”。证据不足的尺寸、颜色和组件行为必须标记`候选/待确认`，不得包装为固定事实。

### 外壳

- 左侧菜单宽度约 `210px`
- 顶部业务域导航高度约 `50px`
- Tags-View 位于顶部导航下方
- 页面背景约 `#F2F3F5`
- 内容区白底容器为主

### 主色与语义色

- 品牌导航蓝：`#1C53D9`
- 主按钮蓝：`#409EFF`
- 成功新增绿：`#67C23A`
- 编辑警示黄：`#E6A23C`
- 危险错误红：`#F56C6C`
- 主文字：`#303133`
- 常规文字：`#606266`
- 弱文字：`#909399`
- 边框灰：`#DCDFE6`

### 字体与密度

- 中文无衬线字体栈，优先 `PingFang SC`
- 输入框 / 表格 / 常规字段约 `14px`
- 顶部导航约 `14-16px`
- 页面保持中高密度，不做夸张留白

## 页面类型骨架

### 工作台 / 门户

默认结构：

1. 工作流或待办
2. 常用入口
3. 公告通知
4. 指标概览
5. 风险 / KPI / 预警 / 设备或库存模块

### 标准列表页

默认结构：

1. Tags-View
2. 筛选区
3. 操作区
4. 表格
5. 分页

默认包含：

- 搜索
- 重置
- 展开
- 新建 / 导出 / 刷新 / 列设置等辅助动作

### 单据新建 / 编辑页

默认结构：

1. 顶部操作条
2. 页面标题
3. 基础字段区
4. 明细表格区
5. 附件 / 备注 / 事由

### 详情页

默认结构：

1. 返回条
2. 标题区
3. 基础信息表格
4. Tabs 分组
5. 明细、日志、审批流程、附件

### 配置页

默认结构：

1. 左侧配置菜单或顶部 Tabs
2. 当前配置类别内容
3. 配置表格
4. 新增 / 编辑 / 启停

### 看板页

默认结构：

1. 页面标题
2. 维度切换
3. 指标卡
4. 图表模块
5. 明细或排行

## 必须保留的交互基因

- 顶部业务域切换左侧菜单
- 页面打开后进入 Tags-View
- 列表页支持查询、重置、展开
- 表格支持分页
- 复杂页面通过新页签打开
- 状态和按钮展示受流程影响

## 禁止项

出现以下内容，必须主动纠正：

- 大 hero 首屏
- 营销 Banner
- 大面积渐变 / 光效 / 装饰球
- 深色科技大屏默认化
- 把表格改成卡片流
- 复杂单据放入小弹窗
- 隐藏后台壳和 Tags-View
- 超大圆角和厚重阴影
- 为了“好看”牺牲后台信息密度

## 输出要求

如果用户要求“按数智工厂 UI 基线生成页面”，输出时至少要保证：

1. 说明使用了本系统 UI 基线
2. 指明页面所属类型
3. 指明沿用了哪些系统壳与组件规则
4. 指明本次是否有偏离基线的特批项
5. 如有同步，给出 `workspace-ui-baseline-sync.md` 的最新结果路径

同时必须输出一份基线证据矩阵：

| 基线项 | 当前值/规则 | 来源文件与位置 | 证据类型 | 置信度 | 冲突/待确认 |
|---|---|---|---|---|---|
| 系统壳/颜色/字体/间距/圆角/表格/表单/弹窗/状态 |  | 截图、CSS、HTML、规范章节 | 明示/测量/推断 | 高/中/低 |  |

## 提取与验收步骤

1. 盘点至少一个系统壳、一个列表页、一个新增/编辑页、一个详情页；缺少的页面类型明确记录，不虚构。
2. 从CSS变量/计算样式提取颜色、字号、行高、间距、圆角、阴影、控件高度；截图测量只能作为辅助。
3. 对比规范、HTML/CSS和截图，列出一致点、冲突和采用建议，由产品确认冲突项。
4. 将基线转为可执行token和组件/页面规则，不只写形容词。
5. 生成页面后在1440x900、1180x800及项目目标窄屏检查系统壳、表格、弹窗、溢出和交互状态。
6. 对照代表性页面截图做视觉差异检查；未实际检查不得写PASS。

不得因为基线技能而修改业务字段、状态、权限或流程。视觉优化与业务结论冲突时，以已确认PRD为准并记录冲突。
