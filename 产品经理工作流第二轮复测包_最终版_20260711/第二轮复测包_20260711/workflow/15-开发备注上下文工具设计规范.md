# 开发备注上下文工具设计规范

## 1. 目标

开发备注不是在空白抽屉里复制一份PRD，也不是为了证明“页面有备注按钮”。它的目标是让开发在不离开当前HTML、不反复搜索PRD的情况下，快速回答：

- 这个页面为什么存在，入口和返回路径是什么？
- 当前字段从哪里来、是否必填、如何校验、如何联动？
- 当前按钮什么状态下出现，点击后调用什么动作，成功/失败如何反馈？
- 当前记录如何流转，哪些角色能看和操作？
- 数据来自哪个接口或Mock，提交参数和返回结果是什么？
- 哪些内容已确认，哪些仍待产品或研发确认？

正式PRD仍是业务范围和决策依据；页面内工具负责“快速定位与实现走读”。

## 2. 不合格形态

以下任一情况不能通过开发备注验收：

- 点击按钮后出现大块空白页面，只堆连续文字。
- 把整份PRD复制进抽屉，没有页面、字段和控件定位。
- 只写“点击后跳转”“按权限控制”等无法开发的空话。
- 没有字段来源、校验、状态、权限、数据和异常说明。
- 备注遮挡页面，开发无法边看页面边看说明。
- 页面修改后备注仍保留旧字段、旧状态或错误基线。

## 3. 推荐交互形态

### 3.1 桌面端

使用右侧可调整宽度的上下文面板，建议宽度360-480px：

- 页面主体保持可操作，不跳到独立空白页。
- 面板可固定、收起、关闭和调整宽度。
- 支持“跟随选择”：点击页面字段、按钮、表格列或状态标签，面板自动定位对应说明。
- 被说明的页面元素显示轻量高亮和编号，例如`F-03`、`A-02`、`S-01`。
- 面板滚动不影响页面主体；页面主体仍可点击验证。

### 3.2 移动端

使用底部抽屉或独立开发模式，不占用最终用户页面宽度。真实移动端交付默认隐藏开发工具，通过开发参数或明确入口开启。

## 4. 信息架构

面板顶部固定显示：页面名称、页面编号、原型用途、当前版本、PRD依据、待确认数量。

使用以下Tab，不把全部内容堆在一个长页面：

| Tab | 开发需要看到的内容 |
|---|---|
| 页面 | 页面用途、菜单路径、入口、返回路径、页面状态、上下游页面 |
| 字段 | 字段名、控件、类型、来源、必填、默认值、校验、枚举、联动、提交键、只读条件 |
| 交互 | 按钮/控件、显示条件、前置状态、点击结果、成功反馈、失败反馈、二次确认、返回同步 |
| 状态 | 状态机、允许动作、下一状态、终态限制、台账/关联数据变化 |
| 权限 | 角色、菜单、数据范围、字段读写、按钮可见/禁用、越权反馈 |
| 数据/API | 数据来源、Mock说明、查询参数、提交参数、返回字段、刷新时机、错误码/失败处理 |
| 异常 | 空态、无权限、校验失败、接口失败、重复操作、边界值和恢复方式 |
| 待确认 | 问题、影响、建议、确认角色、最晚确认阶段、当前状态 |

简单页面可以合并Tab，但页面、字段、交互、状态/权限、数据、待确认六类信息不能缺失。

## 5. 页面内定位

### 5.1 标识规则

| 类型 | 前缀 | 示例 |
|---|---|---|
| 页面 | P | P-01列表页 |
| 字段 | F | F-03申请单号 |
| 动作 | A | A-02审核通过 |
| 状态 | S | S-01待审批 |
| 权限 | R | R-02审批人 |
| 接口/数据 | D | D-01列表查询 |

### 5.2 双向联动

- 点击页面元素 → 打开备注面板并定位说明。
- 点击备注条目 → 页面滚动到元素并高亮。
- 当前页面切换、Tab切换或打开详情后 → 面板自动切换到对应页面说明。
- 高亮必须可关闭，不得改变业务布局和交互结果。

## 6. 字段说明最低结构

| 属性 | 示例 |
|---|---|
| 编号/字段 | F-03 申请单号 |
| 控件/数据类型 | 文本输入 / string |
| 来源 | 系统自动生成 / 用户输入 / 上游接口 |
| 必填与默认 | 必填；默认空 |
| 校验 | 20字符以内；唯一；保存草稿时可空、提交时必填 |
| 枚举/联动 | 选择工厂后过滤库存地点 |
| 读写条件 | 待提交可编辑，待审批后只读 |
| 提交/返回键 | applicationNo |
| 异常反馈 | 重复时提示“申请单号已存在” |

## 7. 动作说明最低结构

| 属性 | 示例 |
|---|---|
| 编号/动作 | A-02 审核通过 |
| 可见角色/状态 | 审批人；待审批 |
| 前置校验 | 审批备注500字以内 |
| 二次确认 | 是；“确定通过审核？” |
| 成功结果 | 状态变为待员工确认；更新详情和返回列表 |
| 失败结果 | 保持原状态；显示失败原因；允许重试 |
| 数据/API | POST /applications/{id}/approve |
| 关联影响 | 暂不写入积分台账 |

## 8. 实现层要求

- 页面元素使用`data-dev-id`与备注条目建立稳定映射，不依赖易变化的CSS选择器或文案匹配。
- 备注数据优先使用结构化JSON/JS对象，不把全部说明硬编码为HTML段落。
- 支持按关键词或编号搜索字段、按钮和状态。
- 支持复制字段名、枚举、接口键或当前条目。
- 待确认项显示数量和状态：待产品、待研发、已确认。
- 备注面板默认不参与业务提交，不改变Mock数据和状态机。
- 生产/最终展示模式可一键隐藏开发工具。

## 9. 最低可用版与推荐完整版

### 最低可用版

- 右侧面板而非空白独立页。
- 页面、字段、交互、状态/权限、数据、待确认分组。
- 每个关键字段和动作有编号。
- 点击备注可定位页面元素。
- 明确PRD依据与当前版本。

### 推荐完整版

- 页面与备注双向定位。
- 搜索、过滤、复制和待确认计数。
- 页面切换自动同步上下文。
- 结构化数据源，可自动检查页面控件与备注覆盖率。
- 开发模式/演示模式切换。

## 10. 验收清单

- [ ] 备注不是空白页或连续长文本。
- [ ] 面板打开后仍可操作和观察主页面。
- [ ] 页面、字段、交互、状态、权限、数据、异常、待确认结构完整。
- [ ] 所有关键字段、按钮和状态有稳定编号。
- [ ] 页面元素与备注至少实现单向定位，开发实现原型推荐双向定位。
- [ ] 说明包含实现条件和结果，不是空泛描述。
- [ ] 页面改动后已同步备注，没有旧字段和旧状态。
- [ ] 开发工具可隐藏，不污染真实移动端和最终展示。
- [ ] 开发人员能在30秒内找到一个字段来源、一个按钮结果和一个待确认项。

出现空白说明页、仅长文本、无上下文定位或关键控件无说明，开发备注判定`FAIL`。
