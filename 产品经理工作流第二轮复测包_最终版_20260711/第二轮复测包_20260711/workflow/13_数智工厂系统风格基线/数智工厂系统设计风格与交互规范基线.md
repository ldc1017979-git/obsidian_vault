# 数智工厂系统设计风格与交互规范基线

采集日期：2026-07-02  
采集对象：数智工厂 Web 系统  
用途：作为后续工作流生成原型、做系统改造、扩展新模块时的风格和交互对齐依据。本文不保存登录账号和密码。

## 1. 总体判断

该系统是典型的工厂数字化 / 业务运营后台，不是营销型网站，也不是重视觉大屏产品。核心气质是：

- 高密度业务操作后台
- 多模块、多单据、多流程的企业管理系统
- 以表格、表单、详情、审批流、指标看板为主要页面形态
- 视觉上克制、清晰、偏工具型
- 交互上重视查询、筛选、分页、明细、状态、单据流程和横向多页签工作

后续任何原型生成都应该优先保持“业务后台工具感”，不要做成 landing page、营销页、过度装饰化 dashboard、深色科技大屏或大面积插画风。

## 2. 技术与组件基因

从页面 DOM、样式类名和组件表现判断，系统主要基于 Vue + Element Plus 风格体系构建。

典型组件类包括：

- `el-button`
- `el-input`
- `el-select`
- `el-date-picker`
- `el-table`
- `el-tabs`
- `el-pagination`
- `el-drawer`
- `el-dialog`
- `el-switch`
- `el-upload`

后续做原型时，应优先复用 Element Plus 式组件语法和视觉，而不是重新发明一套控件风格。

## 3. 色彩体系

### 3.1 核心颜色

- 品牌/导航蓝：`#1C53D9`
- Element 主按钮蓝：`#409EFF`
- 看板局部高亮蓝：`#2F67F6`
- 成功/新增绿：`#67C23A`
- 编辑/警示黄：`#E6A23C`
- 危险/错误红：`#F56C6C`
- 信息灰：`#909399`
- 页面背景灰：`#F2F3F5`
- 边框灰：`#DCDFE6`
- 主文字：`#303133`
- 常规文字：`#606266`
- 弱文字：`#909399` / `#999999`

### 3.2 颜色使用规则

- 蓝色用于主流程动作、查询、导航激活、当前页签、数据强调。
- 绿色用于新增、添加、创建类动作，例如“新建采购单”“新增分类物料组”“添加”。
- 黄色用于编辑类动作，例如设置页表格中的“编辑”。
- 红色用于错误、必填校验、风险、异常状态。
- 灰白用于取消、重置、普通辅助操作。
- 不使用大面积渐变背景，不使用花哨霓虹色，不使用厚重深色科技背景。

## 4. 字体与信息密度

### 4.1 字体

系统主要使用：

- `PingFang SC`
- 系统无衬线字体
- Element Plus 默认字体栈

### 4.2 字号层级

- 顶部导航：约 14-16px
- 左侧菜单：约 14px，激活项中等字重
- 页签：约 13px
- 表格：约 14px
- 输入框：约 14px
- 工作台模块标题：约 18-20px，偏粗
- 看板页主标题：约 24px
- 指标大数字：约 36-48px，局部加粗

### 4.3 信息密度

整体是中高密度后台系统。页面应尽量节省纵向空间：

- 不做超大留白
- 不做夸张 hero 区
- 不把每个字段做成大卡片
- 表单、筛选区、表格要紧凑排列
- 复杂单据允许横向滚动表格

## 5. 全局页面框架

### 5.1 外壳结构

系统采用固定后台外壳：

- 左侧一级/二级模块导航，宽度约 210px
- 顶部横向业务域导航，高度约 50px
- 顶部右侧包含全局搜索、通知、上传/云图标、全屏、用户入口
- 顶部下方有 Tags-View 多页签
- 主内容区在右侧，背景为浅灰 `#F2F3F5`

### 5.2 顶部业务域导航

顶部横向业务域包括：

- 运营中心
- 仓储管理
- 生产管理
- 质量管理
- 设备管理
- 安全管理
- 人事行政
- 财务管理
- 数据统计
- 综合管理
- 数据看板
- 设置

规则：

- 当前业务域使用蓝色文字和蓝色下划线。
- 顶部导航保持白底。
- 不使用大面积色块作为顶部导航背景。
- 顶部导航承载模块切换，不承载具体业务表单内容。

### 5.3 左侧菜单

左侧菜单根据顶部业务域动态切换。样式特点：

- 宽度约 210px
- Logo 区高度约 84px
- 菜单项高度约 58px
- 常规菜单为白底、黑灰文字、线性图标
- 激活菜单为浅蓝背景 `#EDF1FC`，蓝色文字 `#1C53D9`
- 激活菜单左侧有蓝色点/标识
- 有二级菜单时使用 `>` 或类似符号提示

后续原型应保持左侧菜单的“模块导航”属性，不应把左侧做成信息卡、营销文案区或复杂树状大面板。

### 5.4 Tags-View 页签

系统支持多页面横向页签。样式特点：

- 位于顶部导航下方
- 默认高度约 28-32px
- 活跃页签浅蓝底 `#ECF5FF`
- 活跃页签蓝色边框 `#409EFF`
- 圆角很小，约 2px
- 页签可关闭

复杂业务跳转后会新增页签，例如：

- 工作台
- 全部采购订单
- 采购单详情
- 新建采购单
- 基础设置
- 原料今日检测

后续原型若涉及多业务页面，必须保留页签式工作区，不要只用单页面面包屑替代。

## 6. 页面类型规律

### 6.1 工作台首页

工作台是门户 + 看板混合页。

主要模块：

- 工作流控中心
- 常用速达区
- 公告通知
- 生产系统达成概况
- 安/质/环风险预警台
- KPI 考核指标
- 一般考核指标
- 基地设备实况
- 库存预警

视觉特点：

- 页面背景浅灰
- 内容模块为白色卡片
- 卡片圆角约 8px
- 卡片间距约 10-12px
- 模块标题左侧常带业务图标
- 数字指标使用蓝色或状态色强化
- 表格混合在卡片中，不单独做夸张视觉

工作台适合展示“待办、常用入口、公告、生产达成、风险预警、库存预警、KPI”等概览信息。

### 6.2 标准列表管理页

采购订单列表是标准样本。

结构顺序：

1. 顶部 Tags-View 页签
2. 筛选区白色容器
3. 操作区
4. 数据表格
5. 分页器

筛选区特点：

- 白底卡片
- 字段横向排列
- 常见字段为关键字、单号、商品名称、日期范围、部门、分类、月份范围
- 输入框高度约 32px
- 搜索按钮为蓝色主按钮
- 重置为灰白普通按钮
- 展开为灰白普通按钮
- 筛选项过多时通过“展开”显示更多

表格特点：

- 表头浅蓝/浅灰底
- 表格线清晰但不重
- 多列横向滚动
- 单元格内容允许省略号
- 操作列固定在右侧
- 行操作多用链接按钮，例如“详情”“反审”
- 状态字段以文字或小标签呈现，例如“待提审”“待入库”“未结算”

分页特点：

- 底部右侧或底部区域显示
- 包含总数、每页条数、页码、前往页
- 当前页蓝底

### 6.3 详情页

采购单详情是复杂单据详情页样本。

结构顺序：

1. 顶部返回按钮条
2. 白色详情容器
3. 标题区：标题 + 打印/辅助操作
4. 基础信息表格
5. Tabs 信息分组
6. 明细表格
7. 合计、采购事由、备注、附件

详情页特点：

- 复杂单据使用独立路由，不用弹窗承载
- 返回按钮为浅蓝描边/主色 plain 样式
- 基础信息用表格形式展示
- 字段标签格为浅灰底
- 值区域为白底
- 状态标签使用浅蓝底/边框
- 明细信息仍以表格为核心
- Tabs 包含采购单详情、待入库、退货信息、冲销信息、入库信息、单据日志、审批流程等

后续复杂详情页应保持这种“信息表格 + 明细表格 + Tabs”的组织方式。

### 6.4 新建 / 编辑单据页

新建采购单是复杂表单页样本。

结构顺序：

1. 顶部固定操作条：取消、下一步
2. 主体白色容器
3. 页面标题：新建采购单
4. 标题旁工具按钮：导入货品
5. 提示语：横向滚动说明
6. 基础字段区
7. 明细操作区：添加、批量添加
8. 附加字段：采购事由、备注、附件
9. 明细表格

表单特点：

- 复杂单据新建使用独立路由
- 顶部操作条优先展示流程动作
- 基础字段采用多列横向布局
- 必填字段使用红色 `*`
- 禁用字段灰底
- 下拉、日期、选择器统一为 Element 风格
- 明细表格可横向滚动
- 空表格状态显示“暂无数据”
- 上传使用 plain 蓝色按钮

交互特点：

- “下一步”是主流程按钮
- “取消”是普通按钮
- “添加”为绿色
- “批量添加”为蓝色
- 若前置字段缺失，先在字段下方出现红色校验提示，例如“请选择供应商”，再阻止后续动作

### 6.5 设置 / 基础配置页

基础设置页是配置型页面样本。

结构：

- 左侧设置模块菜单
- 内容区顶部 Tabs
- 当前 Tab 下方操作区
- 配置表格

特点：

- 设置菜单左侧仍保持系统统一侧栏风格
- 内容区以 Tabs 切换配置类别，例如货品分类、计量单位、部门管理、使用地点、移动类型、领料类型
- 新增按钮为绿色
- 编辑按钮为黄色 warning
- 表格列较少，行距比采购订单列表略舒展
- 不需要复杂筛选时不强行增加筛选区

### 6.6 数据看板页

数据看板页不是深色全屏大屏，而是保留后台壳的白底指标看板。

样本：原材料检测（今日）

特点：

- 仍保留左侧菜单、顶部导航、Tags-View
- 页面标题较大，例如“原材料检测（今日）”
- 顶部有分段 Tab，例如“全部 / 红牛 / 战马”
- 内容区使用白底或极浅底
- 指标块与 ECharts 图表结合
- 大号数字突出关键指标
- 使用蓝、绿、红、橙等状态色表达检验结果
- 图表风格清爽，不是深色科技风
- 模块圆角可更大，观察到看板卡片约 16px 圆角

后续除非明确要求“大屏驾驶舱”，否则看板类页面不要改成黑蓝全屏大屏。

## 7. 组件规范

### 7.1 按钮

按钮体系：

- 主按钮：蓝色，`#409EFF`，用于搜索、下一步、导入、确认
- 新增按钮：绿色，`#67C23A`，用于新建、添加、新增分类
- 编辑按钮：黄色，`#E6A23C`，用于编辑配置项
- 危险按钮：红色，`#F56C6C`，用于删除、作废等高风险动作
- 普通按钮：白底灰边，用于取消、重置、展开、全部展开/折叠
- 链接按钮：蓝色文字，用于表格行内操作，例如详情、保存、重置

尺寸特点：

- 常规按钮高度约 32px
- 主要流程按钮可固定宽度约 100px
- 按钮圆角约 4px
- 图标 + 文本组合很常见

### 7.2 输入框与选择器

输入框特点：

- 高度约 32px
- 白底
- 4px 圆角
- 内阴影式边框
- placeholder 为浅灰
- 下拉框右侧有箭头
- 日期框左侧常有日历图标
- 范围选择器使用“开始 - 结束”结构

### 7.3 表格

表格是系统最核心的承载组件。

规则：

- 表头浅色背景
- 单元格边框清晰
- 列多时允许横向滚动
- 操作列放最右
- 数字列可居中或右对齐
- 状态列使用标签或短文本
- 行内操作不要做大按钮，优先链接按钮或小型按钮
- 空状态显示“暂无数据”

### 7.4 Tabs

Tabs 用于详情分组、配置类别、看板维度。

两种常见形式：

- Element Tabs：蓝色文字 + 下划线，用于设置页、详情页
- 分段按钮 Tabs：激活态蓝底白字，用于看板页“全部/红牛/战马”

### 7.5 弹窗与抽屉

系统存在 `el-dialog` 和 `el-drawer` 能力，但从复杂单据观察：

- 复杂详情、新建、编辑优先使用独立路由
- 选择类、批量添加类、辅助配置类可以使用抽屉或弹窗
- 抽屉底部/头部常有“确认选择”“关闭”
- 弹窗按钮顺序一般为“确定 / 取消”

后续不要把复杂单据塞进小弹窗；弹窗只适合轻量确认、选择、配置。

### 7.6 状态标签与校验

状态标签：

- 待提审：浅蓝标签
- 待入库：文字/标签状态
- 未结算：表格文字状态

表单校验：

- 必填项使用红色 `*`
- 缺失时在字段下方显示红色提示
- 先校验前置字段，再允许后续选择/批量添加动作

## 8. 交互方式

### 8.1 导航交互

- 顶部业务域切换左侧模块菜单
- 左侧模块可进入业务页面
- 有二级菜单时通过浮层/展开呈现
- 打开页面后生成 Tags-View 页签
- 用户可在多个业务页签之间切换

### 8.2 查询交互

标准流程：

1. 用户输入筛选条件
2. 点击“搜索”
3. 表格刷新
4. 点击“重置”清空条件
5. 条件较多时点击“展开”显示更多筛选项

### 8.3 列表操作

列表页常见动作：

- 新建
- 详情
- 编辑
- 反审
- 刷新
- 密度/列设置
- 分页切换

复杂操作不直接在表格中展开大表单，而是跳转到详情/新建/编辑页。

### 8.4 单据流程

复杂单据常见路径：

1. 列表页查看数据
2. 点击“新建”进入独立新建页
3. 填写基础信息
4. 添加明细
5. 点击“下一步”
6. 进入后续流程或审批

详情页常见路径：

1. 列表点击“详情”
2. 进入独立详情页
3. 查看基础信息、明细、入库/退货/日志/审批流
4. 必要时打印单据或返回

### 8.5 工作台交互

工作台入口强调快速到达：

- 我的待办
- 我发起的
- 我处理的
- 抄送我的
- 与我相关
- 常用速达区

这些是首页优先级高的功能，后续改造首页时要保留“快速处理事务”的逻辑。

## 9. 后续原型生成约束

### 9.1 必须继承

- 后台壳：左侧 210px 菜单 + 顶部 50px 业务域导航 + Tags-View
- 浅灰页面背景 + 白色内容容器
- Element Plus 风格组件
- 蓝色主色、绿色新增、黄色编辑、红色错误/危险
- 高密度表格、表单、筛选区
- 复杂单据用独立路由页
- 详情页用基础信息表格 + Tabs + 明细表格
- 新建页用顶部操作条 + 基础字段 + 明细表格
- 看板页保留后台壳和白底清爽图表风

### 9.2 可以适度优化

- 字段分组可以更清晰
- 表格列可增加固定列、列宽、tooltip
- 空状态可以更明确，但不要插画化
- 查询区可以折叠/展开更顺手
- 数据看板可以增强图表可读性
- 页面间距可以略微统一
- 低风险交互可以使用抽屉提升效率

### 9.3 禁止跑偏

- 不做营销落地页风格
- 不做大 hero 首屏
- 不做大面积渐变、光效、装饰球
- 不做暗黑科技大屏，除非单独要求
- 不用大卡片堆满业务表单
- 不把复杂单据放进小弹窗
- 不随意更换主色体系
- 不用过大的圆角和阴影
- 不把表格型页面改成展示型卡片流
- 不隐藏 Tags-View 和多模块后台框架
- 不把首页做成宣传页，首页应是工作台

## 10. 后续工作流使用建议

后续基于该系统链接做项目改造或生成原型时，建议按以下顺序执行：

1. 先判断新增需求属于哪类页面：工作台、列表、详情、新建表单、设置、看板、流程审批。
2. 找本文对应页面类型作为模板。
3. 复用该类页面的布局骨架和组件语义。
4. 只在业务字段、数据结构、流程节点上做变化。
5. 生成后对照“禁止跑偏”逐项检查。
6. 若需求确实需要新风格，必须先明确这是“新增视觉方向”，不能默认替换现有系统风格。
