# Codex 测试指令：基于数智工厂基准生成 HTML 原型

用途：把本文件交给产品或另一个 Codex 会话测试，验证 Codex 是否能读取本文件夹中的系统基准，并生成不跑偏的工厂端 HTML 原型。

重要说明：本文件是固定回归测试题，只用于验证 Codex 是否理解数智工厂基准。采购订单案例不是通用业务模板，不能迁移到积分、设备、质量、安全、生产等真实新增模块。

如果本次输入来自团队测试反馈、试跑复盘、测试报告或负责人要求“同步到工作流”，不要直接生成或修复 HTML。必须先判断这是团队产品测试 / 工作流试跑反馈，输出问题归类、需要同步的工作流文件和下一轮测试安排。只有用户明确说“先修原型/页面/HTML”时，才进入具体制品修复。

## 必须遵守

- 先判断需求属于哪个一级业务域、二级业务子域、业务组和页面类型。
- 当前测试案例是采购订单页面族，只能在本测试中使用。真实项目生成时，不得继承本案例中的采购字段、采购状态、采购动作或采购流程。
- 原型必须保留数智工厂系统的后台壳：左侧菜单、顶部业务域导航、Tags-View、浅灰背景、白色内容区。
- 页面必须使用接近 Element Plus 的后台组件风格：按钮、输入框、选择器、日期范围、表格、Tabs、分页、上传、状态标签。
- 复杂单据必须用独立页面/页签逻辑表现，不要塞进小弹窗。
- 必须体现业务字段、状态字段、操作列、明细表格、日志或审批流程。
- 必须体现按钮颜色语义：蓝色主流程、绿色新增、黄色编辑、红色危险、灰色普通操作。
- 不要做营销页、大 hero、暗黑科技大屏、大面积渐变、装饰性视觉。
- 不要包含账号、密码、token 或真实登录链接。

## 基准使用边界

生成现有系统新增模块时，必须遵守“只取形，不取业务”：

- 可以复用系统壳、布局密度、组件风格、按钮颜色语义、列表/详情/表单/配置页的组织方式。
- 不可以复用测试案例中的业务字段。
- 不可以复用测试案例中的状态流转。
- 不可以复用测试案例中的业务动作。
- 不可以把采购订单的供应商、入库、结算、反审、批量添加、下一步等内容迁移到其他模块。

如果当前业务规则和基准页面结构冲突，优先保证当前业务规则正确，再用数智工厂组件风格承载该业务。

## 测试案例

以下测试案例只用于本文件的固定验证，不代表后续项目都要生成采购订单。

请生成以下业务页面族：

菜单路径：

`仓储管理 > 采购管理 > 原料/备件与综合物资 > 全部采购订单`

页面类型：

- 标准列表页
- 单据新建页
- 单据详情页

页面族路由逻辑参考：

- 列表：`/warehouse-manage/buy/routine-purchase/order`
- 新建：`/warehouse-manage/buy/routine-purchase/order/add`
- 详情：`/warehouse-manage/buy/routine-purchase/order/detail`

## 列表页内容要求

列表页标题：

`全部采购订单`

必须包含：

- 查询区：采购单号、供应商、商品名称、采购部门、采购类型、状态、创建日期范围。
- 操作区：新建采购单、导出、搜索、重置、展开。
- 表格列：采购单号、供应商、采购类型、物料类别、采购部门、采购金额、入库状态、结算状态、审批状态、创建人、创建时间、操作。
- 行操作：详情、编辑、反审。
- 分页器：总数、每页条数、页码、跳转。

状态样例：

- 待提审
- 待审批
- 待入库
- 部分入库
- 已入库
- 未结算
- 已结算
- 已反审

## 新建页内容要求

新建页标题：

`新建采购单`

必须包含：

- 顶部操作条：取消、下一步。
- 基础信息：供应商、采购部门、采购类型、期望到货日期、联系人、联系电话、采购事由。
- 明细区：导入货品、添加、批量添加。
- 明细表格：货品编码、货品名称、规格型号、单位、采购数量、含税单价、税率、金额、到货日期、备注、操作。
- 附件上传区。
- 表单校验：如果未选择供应商，点击“批量添加”或“下一步”时，在供应商字段下方显示红色提示“请选择供应商”。

## 详情页内容要求

详情页标题：

`采购单详情`

必须包含：

- 返回按钮。
- 基础信息表格。
- 状态标签。
- 打印或导出按钮。
- Tabs：
  - 采购单详情
  - 待入库
  - 退货信息
  - 冲销信息
  - 入库信息
  - 单据日志
  - 审批流程
- 采购明细表格。
- 合计金额、采购事由、备注、附件。
- 审批流程中展示提交、审批通过、待下一节点等节点。
