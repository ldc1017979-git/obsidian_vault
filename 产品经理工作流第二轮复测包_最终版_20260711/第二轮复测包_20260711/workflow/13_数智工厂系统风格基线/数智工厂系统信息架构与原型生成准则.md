# 数智工厂系统信息架构与原型生成准则

采集日期：2026-07-02  
采集对象：数智工厂 Web 系统  
用途：作为后续 Codex 工作流生成工厂端原型、改造现有项目、扩展新模块时的基准规则。本文不保存登录账号、密码、token。

## 1. 基准结论

这个系统不是单纯的后台模板，也不是只靠视觉风格就能复刻的管理系统。它的核心是“工厂业务域 + 多级菜单权限 + 单据/记录/报表/配置/看板页面类型 + 状态流转动作”的组合。

重要边界：本基准是“系统规范”，不是“业务模板”。后续新增模块必须先以当前模块已确认的业务规则为准，再使用本基准约束系统外壳、组件风格、页面层级和交互方式。不能把某个基准测试案例里的业务字段、状态、动作或流程迁移到无关模块。

后续做任何工厂端原型，必须先回答四个问题：

1. 这个需求属于哪个一级业务域。
2. 它在菜单中属于哪个二级业务子域和业务组。
3. 它是哪一类页面：列表、单据新建、详情、记录检查、报表统计、基础配置、流程审批、看板或文件知识类。
4. 它的业务对象如何流转，哪些动作受状态和权限控制。

如果只复刻颜色、按钮、表格样式，而没有匹配菜单层级和业务流转，后续原型一定会跑偏。

## 2. 本次整理方法

本次不只基于截图归纳，而是使用了四类证据：

- 页面实测：登录系统并采集工作台、采购订单列表、采购单详情、新建采购单、基础设置、数据看板等代表页面。
- 菜单权限 API：从 `/apios/home/getRoleList` 取得真实 `data.list`、`data.hide`、`data.btn`。
- 前端路由代码：核对菜单节点如何生成路由、页面标题、隐藏页和视图组件。
- 结构化归档：将菜单树、隐藏路由、页面类型、动作权限拆成可复用附录。

在线 skill 调研结论：

- [Codex Design Audit Skill](https://github.com/Kappaemme-git/codex-design-audit-skill)：适合给 URL、截图、本地应用或前端仓库做结构化 UI/UX 审计，能发现弱点、可访问性、响应式和前端打磨问题。
- [design-system-starter](https://github.com/softaworks/agent-toolkit/blob/main/skills/design-system-starter/README.md)：适合建立设计系统、组件一致性和可扩展视觉规则。
- [UI/UX Pro Max Skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md)：适合提供通用 UI/UX 结构、视觉风格、交互和图表规则。
- [Awesome Codex Skills](https://github.com/composiohq/awesome-codex-skills) 和 [Awesome Agent Skills](https://github.com/VoltAgent/awesome-agent-skills)：适合作为后续继续扩展技能库的入口。

这些 skill 对“审计视觉质量、检查响应式、归纳设计系统”有帮助，但不足以单独解决当前问题。原因是数智工厂系统的关键不只是 UI 好不好看，而是菜单权限树、隐藏路由、业务单据流、审批动作和工厂业务分类是否正确。因此本基准采用“通用设计审计能力 + 真实系统结构反向梳理”的组合。当前本地 `playbooks find skill` 检索接口曾返回 502，所以没有直接安装新的外部 skill；本次实际执行使用本机已有 Playwright skill 和数据解析流程。

就当前场景而言，最可靠的组合不是套一个通用视觉审查 skill，而是以下工作流：

- Playwright 页面采集：确认真实页面结构、交互和样式。
- 菜单权限树反向梳理：确认系统信息架构和路由层级。
- 前端路由逻辑核对：确认 hidden route、add/detail/tools 页如何生成。
- 视觉规范沉淀：把颜色、组件、布局、交互归入页面类型规则。

## 4. 系统总体定位

系统定位是高密度工厂数字化运营后台，面向多部门、多基地、多流程的业务处理。

主要特征：

- 顶层按工厂业务域组织，而不是按页面样式组织。
- 页面以表格、筛选、单据、明细、审批、记录、报表、指标看板为主。
- 业务操作强调状态、权限、流程、日志和附件。
- 同一个业务对象通常有列表页、隐藏新建页、隐藏详情页、审批/日志/工具页。
- 复杂页面使用独立路由和 Tags-View，不用小弹窗承载。
- 视觉克制、工具化、数据密度高。

## 5. 系统层级结构

### 5.1 层级模型

系统的真实层级来自 `data.list` 菜单树：

| 层级 | 含义 | 原型生成时的作用 |
| --- | --- | --- |
| Level 0 | 一级业务域 | 顶部横向导航或系统级入口 |
| Level 1 | 二级业务子域 | 左侧菜单一级分组 |
| Level 2 | 业务组/业务对象组 | 左侧菜单分组或展开项 |
| Level 3-5 | 具体页面/更细业务对象 | 左侧叶子菜单或深层业务页面 |
| hide=1 | 隐藏路由/动作页 | 新建、详情、编辑、工具页，不出现在常规菜单 |
| btn | 按钮权限标识 | 控制新增、编辑、审批、驳回、导出等动作 |

不能只根据标题中的 `﹥` 判断层级。真正层级必须看 `_children`、`pid`、`page_path` 和最终 `route`。

### 5.2 顶部业务域与特殊入口

从可见顶层菜单看，常规顶部业务域主要包括：

- 运营中心
- 仓储管理
- 生产管理
- 质量管理
- 设备管理
- 安全管理
- 人事行政
- 财务管理
- 数据统计
- 综合管理
- 数据看板
- 设置

原始 `data.list` 中还存在：

- 数据中心
- 公告预览页
- 公告中心
- 异步下载中心

这些不能简单等同为普通顶部业务模块。`数据中心` 更像数据分析结构域，其中部分子节点存在页面，部分是占位或未发布节点；公告预览、公告中心、异步下载中心属于系统级功能入口或特殊路由，不应在普通工厂业务原型里当成常规一级模块。

### 5.3 节点类型判断

菜单节点应这样判断：

| 节点特征 | 判断 | 原型处理 |
| --- | --- | --- |
| `hide=0` 且有 `_children` | 可见菜单分组 | 作为导航层级保留 |
| `hide=0` 且有 `local_url` | 可见实际页面 | 作为业务页面生成 |
| `hide=0` 但无 `local_url` | 目录、占位、未发布或外部入口 | 不要默认生成完整 CRUD |
| `hide=1` 且 `page_path` 含 `add` | 隐藏新建页 | 通过列表页按钮进入独立路由 |
| `hide=1` 且 `page_path` 含 `detail` | 隐藏详情页 | 通过行操作进入独立路由 |
| `hide=1` 且 `page_path` 含 `tools` | 工具/选择/辅助页 | 可用独立页、抽屉或弹窗，视复杂度决定 |
| `btn_identity` 或 `data.btn` | 权限动作 | 按钮必须体现状态/权限控制 |

### 5.4 路由生成逻辑

前端路由逻辑可以归纳为：

- `route = parent route + page_path`，并清理重复斜杠。
- `component = /src/views + local_url + .vue`。
- `meta.title = auth_title`。
- `meta.hidden = hide`。
- `meta.keepAlive = true`。
- 隐藏节点如果标题是“列表”，并且是菜单节点，会被前端转换为“新建 + 父级标题”。
- 所有路由挂到统一 `layout` 下，所以页面应保留后台壳和 Tags-View。

后续做原型时，新增页面路由要遵循这个结构。例如：

- 列表：`/warehouse-manage/buy/routine-purchase/order`
- 新建：`/warehouse-manage/buy/routine-purchase/order/add`
- 详情：`/warehouse-manage/buy/routine-purchase/order/detail`

## 6. 一级业务域准则

### 6.1 运营中心

定位：经营与生产指标门户，面向管理层概览。

二级结构：

- 生产经济技术指标
- 经济数据指标
- 公司级年度重点工作
- 部门级年度重点工作

原型准则：

- 优先做指标卡片、趋势图、任务达成、KPI、年度重点工作跟踪。
- 页面可以比普通列表更看板化，但仍保持后台壳。
- 不做营销首页，不做宣传型大图首屏。
- 任务类页面要有状态、负责人、时间节点、完成进度、跟踪记录。

### 6.2 仓储管理

定位：采购、库房、库存、叉车、仓储报表、基础资料的核心业务域。

二级结构：

- 采购管理
- 库房管理
- 叉车管理
- 报表
- 基础信息

核心业务链：

- 需求计划
- 采购订单
- 采购入库
- 原料到货验收与送检
- 原料/备件/综合物资库存
- 出库、领料、退料、调拨、盘点、报废
- 冲销、退货、结算
- 仓储报表和基础资料

原型准则：

- 仓储类页面以“单据 + 明细表格 + 状态流转”为主。
- 列表页必须包含筛选、表格、分页、状态列、操作列。
- 单据详情应包含基础信息、物料明细、附件、备注、单据日志、审批流程或相关记录。
- 新建页应包含基础字段、供应商/仓库/物料选择、明细添加、上传附件、前置校验。
- 报表页强调查询条件和导出，不要强行做成卡片大屏。
- 基础信息页强调分类、供应商、货品、仓库、库位、温度标准、版本信息等配置。

### 6.3 生产管理

定位：生产过程、扫码、称量、物料平衡、生产记录、生产计划与基础资料。

二级结构：

- 过程管理
- 生产库存报表
- 生产基础信息
- 生产计划管理

核心业务链：

- 生产计划
- 批生产指令/生产订单
- 物料领用与称量
- 配方箱/配方桶/咖啡因/VB12 等过程对象
- 开机、停机、巡检、交接班、清场
- 物料平衡、异常损耗、退库
- 生产日报、月报、KPI

原型准则：

- 生产域大量页面是记录表和检查表，不能全部套成采购单样式。
- 记录页要保留班次、产线、产品、批次、时间、操作人、复核人等工厂过程字段。
- 物料平衡类页面要有投入、产出、损耗、差异、复核和异常处理。
- 称量/扫码类页面要突出批次、扫码结果、称量数值、复核状态。
- 计划/订单类页面可使用单据流转骨架。

### 6.4 质量管理

定位：QC 检测、QA 保证、计量管理、质量基础标准和追溯。

二级结构：

- QC质量控制
- QA质量保证
- 计量管理
- 基础信息管理
- 追溯管理

核心业务链：

- 原材料检测
- 成品检测
- 工序控制
- 复检、异常处置、隔离、返工
- 留样、取样、环境检测
- QA 日自查、周排查、审核
- 计量仪器、校准、使用记录
- 标准值、版本、检查项目配置
- 追溯查询

原型准则：

- 质量页面字段更专业，必须保留检测项目、标准值、实测值、判定结果、检验人、复核人、样品批次。
- 检验报告类页面应使用“报告基础信息 + 检测明细表 + 结论 + 签名/复核”的骨架。
- QA 排查类页面应包含项目配置、部门自查、问题清单、整改闭环。
- 计量类页面应包含仪器台账、使用记录、校准/验证、有效期。
- 质量异常类页面要体现状态和处理闭环，不能只做普通列表。

### 6.5 设备管理

定位：能源、设备运行、维保、点巡检、设备报表和自动化整改。

二级结构：

- 能源管理
- 预防性维保
- 点巡检管理
- 设备运行管理
- 能耗 / 设备报表
- 设备自动化整改

核心业务链：

- 仪表配置与数据采集
- 能耗补录与统计
- 保养计划、保养工单
- 点巡检内容、计划、记录
- 设备运行、停机、检修、交接班
- 能耗/设备报表
- 自动化整改事项跟踪

原型准则：

- 设备域要区分“配置类、采集类、工单类、巡检类、报表类”。
- 工单详情必须有设备信息、计划/实际时间、处理记录、备件、图片附件、验收。
- 点巡检页面必须有点位、项目、标准、结果、异常、整改。
- 能源页面可使用图表，但不能脱离查询、表格、导出和后台壳。

### 6.6 安全管理

定位：安全制度、培训、现场特殊作业、双重预防、消防、环境、内外部审核。

二级结构：

- 目标职责
- 制度化管理
- 教育培训
- 现场管理
- 双重预防工作机制
- 应急管理
- 事故管理
- 持续改进
- 消防
- 环境保护
- 内部审核
- 外部审核

核心业务链：

- 安全制度与职责
- 教育培训与体检
- 特殊作业申请和作业证
- 隐患上报、整改、复查
- 消防点巡检和台账
- 环保记录
- 内审/外审任务和执行

原型准则：

- 安全域页面要突出风险等级、隐患状态、责任人、整改期限、复查结论。
- 特殊作业类页面不是普通审批单，要包含作业类型、作业地点、危险因素、安全措施、气体检测、许可签批。
- 审核类页面要有审核计划、检查项、问题项、整改跟踪。
- 培训类页面要有计划、人员、签到、学时、结果。

### 6.7 人事行政

定位：人事、培训、绩效、行政、食堂、车辆、住宿、公告等综合管理。

二级结构：

- 人事管理
- 行政管理
- 文号管理
- 公告管理

核心业务链：

- 招聘、入职、异动、离职、档案
- 培训计划、记录、学时、月报
- 绩效考核、关键事件、个人/部门绩效
- 考勤、住宿、食堂、车辆、访客
- 公告发布和管理

原型准则：

- 人事页面强调人员档案、组织部门、岗位、日期、状态和附件。
- 培训类页面应有计划、课程、人员、签到、考试/评价、学时。
- 行政类页面常见台账、申请、记录、统计，不要只做卡片展示。
- 公告类页面要区分编辑、发布、预览、阅读状态。

### 6.8 财务管理

定位：经营统计、固定资产、点巡检、降本增效。

二级结构：

- 经营统计
- 固资管理
- 点巡检管理
- 降本增效

核心业务链：

- 成本、费用、预算、采购评审
- 固定资产档案、登记、盘点
- 资产点巡检
- 降本增效事项

原型准则：

- 财务域更偏统计与资产管理，表格字段要重视金额、科目、期间、部门、资产编号。
- 固资页面应有资产档案、登记申请、盘点、状态变更。
- 费用统计页面以查询、汇总、导出为主，不要做成图文展示页。

### 6.9 数据中心

定位：跨业务域的数据分析结构，包含生产、品管、储运、设备、行政人事、安全数据。

二级结构：

- 生产数据
- 品管数据
- 储运数据
- 设备数据
- 行政人事数据
- 安全数据

原型准则：

- 数据中心更多是统计查询和专题分析，不是业务录入主阵地。
- 若节点无 `local_url`，应视为占位、未发布或外部分析入口，不要默认生成完整页面。
- 已有实际页面可按报表统计页处理：查询条件、统计表、图表、导出。

### 6.10 数据统计

定位：按安环、仓储、质量、生产、设备、能源、人事行政汇总的统计看板/分析页。

二级结构：

- 安环
- 仓储
- 质量
- 生产
- 设备
- 能源
- 人事行政

原型准则：

- 数据统计页可更图表化，但仍要保留筛选、维度切换和数据表。
- 适合做指标卡、趋势图、排行、异常明细联动。
- 不应替代业务域内的单据录入页。

### 6.11 综合管理

定位：任务、知识仓库、冲销进度等跨域协同功能。

二级结构：

- 任务管理
- 知识仓库
- 冲销进度

原型准则：

- 任务管理应包含任务列表、任务设置、任务分析、责任人、截止时间、进度、状态。
- 知识仓库应包含文件管理、标签、权限、上传、预览、下载。
- 冲销进度应体现跨单据流程进度，而不是普通静态表。

### 6.12 数据看板

定位：管理层和业务负责人查看关键指标的轻量看板。

可见入口包括：

- 原料今日检测
- 碳足迹
- 成品今日检测
- 安全驾驶舱
- 设备驾驶舱
- 能耗驾驶舱
- 安环
- 质控
- 效率
- 成本
- 人才建设
- 生产驾驶舱
- 储运驾驶舱
- 品管驾驶舱

原型准则：

- 数据看板不是全屏暗黑科技大屏，默认仍保留后台壳和 Tags-View。
- 以白底、浅灰底、指标卡、图表模块为主。
- 可使用较大数字和图表，但不能遮蔽业务筛选和维度切换。
- 除非用户明确要求“大屏驾驶舱”，不要改成深色全屏风格。

### 6.13 设置

定位：系统配置、权限、流程、模板、工作台、采集、组织和菜单。

二级结构：

- 基础设置
- 角色管理
- 账号管理
- 外部账号管理
- 流程设置
- 仓库设置
- 模板中心
- 设置工作台
- 数据采集设置
- 车间产线设置
- 系统操作日志
- 编辑个人工作台
- 组织架构
- 菜单管理

原型准则：

- 设置页通常采用“左侧设置菜单 + 顶部 Tabs + 表格配置”的结构。
- 权限类页面要体现角色、账号、菜单、按钮权限、组织关系。
- 流程设置要体现节点、审批人、条件、启用状态。
- 模板中心要体现模板列表、模板类型、配置、预览、导入导出。
- 数据采集设置要体现采集点位、设备、字段映射、启停状态。

## 7. 页面类型准则

### 7.1 工作台 / 门户

适用：系统首页、运营中心概览、个人工作台。

结构：

1. 工作流控中心。
2. 常用速达区。
3. 公告通知。
4. 生产系统达成概况。
5. 风险预警、库存预警、KPI 等模块。

规则：

- 首页是工作入口，不是宣传页。
- 要有待办、我发起、我处理、抄送、常用入口。
- 模块可以卡片化，但信息密度要高。
- 指标卡、图表、表格可以混排。

### 7.2 标准列表页

适用：采购订单、入库单、记录列表、报表明细、基础资料列表。

结构：

1. Tags-View。
2. 白底筛选区。
3. 操作按钮区。
4. 数据表格。
5. 分页器。

必须包含：

- 搜索、重置、展开。
- 业务关键筛选项。
- 表格列：单号/名称/部门/日期/状态/创建人/更新时间等。
- 操作列：详情、编辑、反审、删除等，按状态出现。
- 分页：总数、每页条数、页码、跳转。

### 7.3 单据新建 / 编辑页

适用：采购单、入库单、领料单、调拨单、盘点单、特殊作业申请、工单。

结构：

1. 顶部操作条：取消、保存、下一步、提交。
2. 页面标题。
3. 基础信息区。
4. 明细表格区。
5. 附件、备注、事由。
6. 底部或顶部流程动作。

规则：

- 复杂单据使用独立路由。
- 基础信息采用多列表单。
- 必填项用红色星号和字段下方校验。
- 明细以表格承载，可横向滚动。
- 新增明细可用绿色按钮，批量添加/导入用蓝色按钮。
- 前置字段未选时，先提示校验，不允许直接进入下一步。

### 7.4 详情页

适用：单据详情、记录详情、报告详情、工单详情。

结构：

1. 返回按钮或返回列表。
2. 标题与辅助操作。
3. 基础信息表格。
4. Tabs 分组。
5. 明细表格、日志、审批流程、附件。

规则：

- 详情页是独立路由，不是弹窗。
- 基础信息常用表格式展示，字段标签浅灰底，值白底。
- Tabs 用于承载详情、待入库、退货、冲销、入库、单据日志、审批流程。
- 打印、导出、反审、撤回等动作按状态和权限出现。

### 7.5 记录 / 检查表页

适用：巡检、点检、清洁、开停机、交接班、体检、培训、检测记录。

结构：

1. 查询区。
2. 记录表格。
3. 新增/导出/批量操作。
4. 详情或编辑页。

规则：

- 字段要体现时间、地点、班次、人员、项目、结果、异常、复核。
- 检查类页面要有检查项目、标准、结果、问题描述、图片附件。
- 巡检类页面要有点位、计划、执行状态、异常闭环。

### 7.6 报表 / 统计查询页

适用：库存报表、成本报表、月报、日报、统计分析。

结构：

1. 查询条件。
2. 汇总指标。
3. 明细表格或透视表。
4. 图表。
5. 导出。

规则：

- 报表页以查询和导出为核心。
- 图表用于辅助理解，不替代表格明细。
- 必须保留期间、部门、物料、产品、基地、状态等维度筛选。
- 不要把报表页做成纯展示卡片流。

### 7.7 基础资料 / 配置页

适用：货品、供应商、仓库、库位、标准值、检查项、角色、账号、组织、流程、模板。

结构：

1. 左侧或顶部配置分类。
2. Tabs 或分组。
3. 表格。
4. 新增、编辑、删除、启停。

规则：

- 配置页可以比单据页更简洁。
- 不需要复杂筛选时不要强行加入大筛选区。
- 编辑可用弹窗或抽屉，复杂配置用独立页。
- 状态字段常见启用/停用。

### 7.8 流程审批页

适用：工作流控中心、流程设置、审批任务、单据审批、审核任务。

结构：

1. 待办/已办/我发起/抄送等视图。
2. 任务列表。
3. 业务单据摘要。
4. 审批记录和流程节点。
5. 审批动作。

规则：

- 审批动作必须受状态控制。
- 常见动作：提交、撤回、通过、驳回、转交、签阅、反审、作废。
- 详情页中应有审批流程 Tab 或日志区。
- 流程设置页面要展示节点、审批人、条件和启用状态。

### 7.9 数据看板页

适用：原料今日检测、成品今日检测、成本、效率、能耗、驾驶舱。

结构：

1. 页面标题。
2. 维度切换或分段 Tab。
3. 指标卡。
4. 图表模块。
5. 明细或排行。

规则：

- 默认白底或极浅底。
- 保留系统壳。
- 使用蓝、绿、红、橙表达状态。
- 驾驶舱可以更大气，但仍要尊重系统的信息密度。

### 7.10 知识 / 文件 / 下载页

适用：公告中心、知识仓库、文件管理、附件清单、异步下载中心。

结构：

1. 分类或标签。
2. 文件/公告列表。
3. 上传、预览、下载、权限。
4. 状态和发布时间。

规则：

- 文件类页面要体现文件名、类型、大小、上传人、上传时间、权限、下载次数。
- 公告类页面要区分草稿、发布、预览、已读。
- 异步下载中心要有任务状态、生成时间、下载入口。

## 8. 动作与状态逻辑

### 8.1 常见动作词

真实按钮权限中高频动作包括：

- `add` / `create`：新增、创建。
- `edit`：编辑。
- `detail` / `details`：详情。
- `submit`：提交或提审。
- `approve`：审批通过。
- `reject`：驳回。
- `review` / `recheck`：审核、复核、复检。
- `recall` / `withdrawal`：撤回。
- `reverse` / `countertrial`：反审、冲销或反向操作。
- `nullify` / `void`：作废。
- `delete` / `del`：删除。
- `import` / `export`：导入、导出。
- `confirm`：确认。
- `sign` / `signature`：签阅、签名。

原型中不能把这些按钮全部固定展示。必须结合状态和权限显示。

### 8.2 通用状态流

常见业务流可以抽象为：

1. 草稿 / 待提交。
2. 待审核 / 待审批。
3. 审批中。
4. 已通过 / 已生效。
5. 执行中。
6. 已完成。
7. 已驳回 / 已撤回。
8. 已反审 / 已冲销。
9. 已作废 / 已删除。

不同页面不一定全部使用，但原型要有状态意识。

### 8.3 列表到隐藏页的流转

真实系统大量使用隐藏路由：

- 列表页是可见菜单。
- 新建页通常是隐藏 `add` 路由。
- 详情页通常是隐藏 `detail` 路由。
- 工具页通常是隐藏 `tools` 路由。

因此后续原型必须保留：

- 列表页点击“新建”打开新页签。
- 列表行点击“详情”打开详情页签。
- 详情页点击“返回”回到列表。
- 复杂工具可进入独立页或抽屉，视复杂度决定。

## 9. 视觉与交互基准

视觉详细规则见《数智工厂系统设计风格与交互规范基线.md》。此处只列原型生成必须遵守的硬规则。

### 9.1 外壳

- 左侧菜单约 210px。
- 顶部业务域导航约 50px。
- 顶部下方保留 Tags-View。
- 主内容背景为浅灰。
- 内容区使用白色容器或白底模块。

### 9.2 组件

- 组件风格以 Element Plus 为主。
- 表格可参考 Element Table / VXE Table 的高密度数据表格形态。
- 常用组件：按钮、输入框、选择器、日期范围、表格、分页、Tabs、Dialog、Drawer、Upload、Switch。

### 9.3 色彩语义

- 蓝色：主流程、查询、确认、导航激活。
- 绿色：新增、添加、创建。
- 黄色：编辑、警示。
- 红色：删除、作废、错误、异常。
- 灰白：取消、重置、普通辅助操作。

### 9.4 禁止跑偏

- 不做营销落地页。
- 不做大 hero 首屏。
- 不做大面积渐变、光效、装饰背景。
- 不默认做暗黑科技大屏。
- 不把表格型业务页改成卡片流。
- 不把复杂单据塞进小弹窗。
- 不隐藏 Tags-View。
- 不随意更换主色体系。
- 不把首页做成宣传页。

## 10. 后续 Codex 原型生成流程

后续每次基于该系统做原型，应按以下流程执行。

### 10.0 第零步：判断项目类型与基准边界

先判断本次任务属于：

- 成熟系统新增模块。
- 旧模块改造。
- 独立新产品。
- 固定回归测试。

如果是成熟系统新增模块或旧模块改造，必须遵守“只取形，不取业务”：

- 可以复用系统壳、布局密度、组件风格、按钮颜色语义、列表/详情/表单/配置页的组织方式。
- 可以参考同类页面的导航层级、隐藏路由关系和交互习惯。
- 不可以复用无关测试案例的业务字段。
- 不可以复用无关测试案例的状态流转。
- 不可以复用无关测试案例的业务动作。
- 不可以为了贴近基准而改变当前模块已确认的业务逻辑。

生成 HTML 前，必须先冻结当前业务硬约束，包括：

- 核心业务对象。
- 页面清单和打开方式。
- 状态机。
- 角色权限。
- 审批、确认、申诉、撤回、作废、删除等规则。
- 明确不做范围。

如果系统风格适配与业务逻辑冲突，以业务逻辑为准，并说明如何用数智工厂组件承载该业务。

### 10.1 第一步：定位业务域

先从一级业务域中选择：

- 仓储、生产、质量、设备、安全、人事、财务、运营、数据、综合、设置。

如果需求跨域，必须说明主域和关联域。例如“原料送检”主域可能在仓储，关联质量检测。

### 10.2 第二步：确定菜单路径

输出格式：

`一级业务域 > 二级业务子域 > 业务组 > 页面`

示例：

`仓储管理 > 采购管理 > 原料/备件与综合物资 > 全部采购订单`

如果找不到完全匹配路径，应选择最接近的同类路径，并说明推断依据。

### 10.3 第三步：选择页面类型

从以下类型选择：

- 工作台 / 门户
- 标准列表页
- 单据新建 / 编辑页
- 详情页
- 记录 / 检查表页
- 报表 / 统计查询页
- 基础资料 / 配置页
- 流程审批页
- 数据看板页
- 知识 / 文件 / 下载页

### 10.4 第四步：定义业务对象和字段

至少定义：

- 业务对象名称。
- 单号或唯一编号。
- 所属部门/基地/产线/仓库。
- 日期或期间。
- 状态。
- 创建人/负责人/操作人。
- 明细对象。
- 附件和备注。
- 日志或审批记录。

### 10.5 第五步：定义动作权限

按页面状态选择动作：

- 列表：搜索、重置、展开、新建、导出、详情、编辑、删除。
- 新建：取消、保存、下一步、提交、添加明细、批量添加、导入。
- 详情：返回、打印、导出、撤回、审批、驳回、反审、作废。
- 配置：新增、编辑、删除、启用、停用。
- 报表：查询、重置、导出、查看明细。

按钮不能无条件全部展示。

### 10.6 第六步：生成页面

页面生成时：

- 保留后台壳。
- 使用对应页面骨架。
- 使用 Element Plus 风格组件。
- 表格、筛选、分页、Tabs 不可缺失。
- 复杂信息用 Tabs 和明细表格组织。
- 必须包含空态、校验态或状态差异中的至少一种。

### 10.7 第七步：验收

使用《工厂端原型生成检查清单.md》逐项验收。

必须通过：

- 信息架构正确。
- 页面类型正确。
- 业务动作合理。
- 视觉风格不跑偏。
- 不包含敏感信息。

还必须做业务污染检查：

- 搜索并清理与当前模块无关的旧测试案例字段。
- 搜索并清理与当前模块无关的状态、动作和流程。
- 搜索并清理演示型、讲解型、汇报型文案。
- 原型改动后，同步更新过程记录、交付清单或说明文档，避免交付物之间口径不一致。

## 11. 快速判断规则

### 11.1 看标题判断页面类型

- 标题含“单、订单、申请、工单、计划、入库、出库、调拨、盘点、报废”：优先按单据页。
- 标题含“记录、检查、巡检、点检、检测、验证、登记”：优先按记录/检查表页。
- 标题含“报表、统计、汇总、月报、日报、查询、明细、台账”：优先按报表页。
- 标题含“基础、配置、设置、标准、档案、类型、规则、模板”：优先按基础配置页。
- 标题含“任务、审批、审核、流程、排查”：优先按流程审批页。
- 标题含“看板、驾驶舱、指标、KPI”：优先按看板或统计页。

### 11.2 看路由判断页面属性

- 末段为 `add`：新建页。
- 末段为 `detail`：详情页。
- 末段为 `edit`：编辑页。
- 末段为 `tools`：工具/选择/辅助页。
- 末段为 `set` 或路径含 `config`：配置页。
- 路径含 `forms`、`report`、`statistics`：报表页。

### 11.3 看业务域判断字段重点

- 仓储：物料、供应商、仓库、库位、批次、数量、单据状态。
- 生产：产线、班次、批次、配方、工序、称量、扫码、交接。
- 质量：样品、检测项目、标准值、实测值、判定、复核、异常。
- 设备：设备、点位、计划、工单、能耗、仪表、巡检、停机。
- 安全：风险、隐患、作业票、整改、责任人、期限、复查。
- 人事：人员、岗位、部门、培训、考勤、绩效、档案。
- 财务：金额、科目、预算、资产、期间、部门、费用。
- 设置：角色、账号、组织、流程、模板、启停状态。

## 12. 示例：采购订单页面族

菜单路径：

`仓储管理 > 采购管理 > 原料/备件与综合物资 > 全部采购订单`

页面族：

- 可见列表页：`/warehouse-manage/buy/routine-purchase/order`
- 隐藏新建页：`/warehouse-manage/buy/routine-purchase/order/add`
- 隐藏详情页：`/warehouse-manage/buy/routine-purchase/order/detail`

列表页应包含：

- 查询条件：单号、供应商、商品名称、日期、部门、状态。
- 操作：新建、导出、搜索、重置、展开。
- 表格：采购单号、供应商、采购类型、金额、状态、创建人、创建时间、操作。
- 行操作：详情、反审等。

新建页应包含：

- 基础信息：供应商、采购部门、采购日期、采购类型。
- 明细表格：物料、规格、单位、数量、价格、金额。
- 辅助：导入货品、添加、批量添加、附件、备注、采购事由。
- 动作：取消、下一步。

详情页应包含：

- 基础信息表格。
- 采购单详情 Tab。
- 待入库、退货、冲销、入库信息。
- 单据日志、审批流程。
- 打印或导出。

这个页面族是后续单据类原型的标准参考之一。

## 13. 最终验收标准

后续任意工厂端原型，只有同时满足以下条件，才算真正对齐该系统：

- 能写出菜单层级，而不是只写页面名称。
- 能判断页面类型，而不是只套一个后台模板。
- 能体现业务对象和状态流转。
- 能体现隐藏新建/详情/工具页的路由逻辑。
- 能体现按钮权限和状态差异。
- 能保持系统外壳、Tags-View、Element Plus 风格和高密度表格表单。
- 能避免营销化、装饰化、暗黑大屏化和卡片流化。

这份准则应作为后续 Codex 工作流的第一上下文；如果具体项目有新系统差异，应在本基准上追加“项目差异说明”，而不是直接覆盖本基准。
