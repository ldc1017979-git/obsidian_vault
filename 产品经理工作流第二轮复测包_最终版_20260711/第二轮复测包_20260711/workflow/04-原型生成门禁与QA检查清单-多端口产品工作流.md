# 原型生成门禁与 QA 检查清单：多端口 + 数智工厂专项

> 版本：2026-07-11修订版。交付前必须按`14-HTML原型完整测试验收SOP.md`执行，并同时填写本清单、`11-交付物版本与口径同步清单.md`和`12-原型真实交互验收记录.md`。

用于 Codex 生成 HTML 原型前后验收。所有端口都先执行通用门禁；如果项目承载在数智工厂现有系统中，再执行数智工厂专项检查。供应链或市场端已有系统，应先读取对应系统资料、规范文档或反推其系统基线。

## 0. 团队测试反馈门禁

如果用户提供的是团队测试反馈、试跑报告、复盘意见或要求“同步到工作流”，Codex 不得直接进入 HTML 生成或修页面。必须先完成以下判断：

- [ ] 这是不是团队产品测试 / 工作流试跑反馈。
- [ ] 反馈对象是某个原型，还是产品工作流本身。
- [ ] 问题属于：任务识别、强引导、资料读取、业务闭环、页面结构、系统基线、交互矩阵、QA、报告结论、团队测试口径中的哪一类。
- [ ] 是否需要修原型。
- [ ] 是否更需要更新通用工作流规则。
- [ ] 是否需要输出下一轮团队测试安排。

团队测试反馈默认产出：

- 本轮测试复盘。
- 工作流修正规则。
- 下一轮团队测试 SOP。
- 反馈表更新建议。
- 需要同步的源文件清单。

只有用户明确要求“先修这个原型”时，才进入原型修复；修复后仍必须补充规则沉淀。

## 2. HTML 生成检查

### 2.1 系统壳

- [ ] 是否符合承载系统的顶部/侧边/页签/面包屑结构。

- [ ] 页面是否像承载系统后台，而不是独立自制后台或营销页。

- [ ] 按钮是否符合承载系统组件风格。
- [ ] 输入框、选择器、日期、上传是否符合承载系统组件风格。

- [ ] Dialog、Drawer、Toast 是否有统一风格。
- [ ] 状态标签是否有明确语义颜色。

### 2.3 页面类型

- [ ] 列表页是否有筛选、重置、展开、表格、分页、行操作。
- [ ] 新增页是否有分组表单、必填、保存、提交、取消。
- [ ] 详情页是否有基础信息、明细、Tabs、日志、审批流程或相关记录。
- [ ] 配置页是否有配置项、状态、编辑、删除或启停。
- [ ] 报表/统计页是否有查询条件、指标、明细和导出。
- [ ] 看板页是否仍保留系统壳，不做全屏暗黑大屏，除非明确要求。

### 2.4 业务逻辑

- [ ] 页面是否覆盖核心业务路径。

### 2.4A 开发备注与字段说明

开发实现原型必须内置开发可主动触发查看的备注入口，可采用浮动按钮、侧边抽屉、折叠面板、右侧说明栏或独立 Tab。该入口用于降低开发阅读成本，不替代 PRD；PRD、字段清单、规则表和页面说明仍作为正式源文档保留。

- [ ] 是否有清晰入口，命名为“开发备注”“逻辑说明”“字段说明”或同等含义。
- [ ] 是否可打开、关闭或收起，不遮挡主流程操作，不影响正常页面验证。
- [ ] 是否覆盖页面用途、业务逻辑、字段解释、状态流转、操作结果、权限差异、数据来源/Mock 说明、异常/空态/边界规则、待确认事项。
- [ ] 字段解释是否包含字段名、含义、来源、必填、校验、枚举、默认值、计算规则或关联关系。
- [ ] 操作说明是否写清按钮触发条件、执行结果、当前页反馈和返回列表同步。
- [ ] 看板类页面是否补充指标口径、统计粒度、数据来源、筛选联动、下钻路径和刷新规则。
- [ ] 是否标明“PRD 仍为正式依据，本说明仅做开发走读辅助”。
- [ ] 是否遵守`15-开发备注上下文工具设计规范.md`，没有做成空白独立页或连续长文本。
- [ ] 是否使用页面、字段、动作、状态编号，并能从备注定位到对应页面元素。
- [ ] 桌面端备注面板打开后，主页面是否仍可查看和操作。
- [ ] 是否按页面、字段、交互、状态、权限、数据/API、异常、待确认分组。
- [ ] 开发人员是否能在30秒内找到一个字段来源、一个按钮结果和一个待确认项。

## 3. 交付前实际结果验证

交付前必须验证实际业务结果，不能只写“按钮可点击”。QA 结论必须区分：

- 页面可打开。
- 数据绑定正确。
- 状态流转正确。
- 当前页刷新正确。
- 返回列表同步正确。
- 角色权限正确。

至少验证：

- [ ] 进入列表页。
- [ ] 筛选和重置。
- [ ] 新增并保存草稿或提交。
- [ ] 必填和字段校验。
- [ ] 查看详情。
- [ ] 点击不同列表行详情时，详情页是否展示当前行对应数据。
- [ ] 编辑后保存。
- [ ] 审批、确认、申诉或核心业务动作。
- [ ] 在详情页执行确认、撤回、作废、删除等动作后，当前详情页和返回列表后的状态是否同步。
- [ ] 删除、撤回、作废二次确认。
- [ ] 配置新增、编辑、删除或启停。
- [ ] 报表、排行榜或看板维度切换。
- [ ] 无权限或异常提示。
- [ ] 返回路径。
- [ ] 如果承载系统有页签，是否验证页签切换。
- [ ] 是否检查新增态为空、编辑态回填、详情态只读、草稿态明确。
- [ ] 是否检查桌面、宽表、弹窗/遮罩、新增空态、员工/用户端入口、移动端或窄屏可读性。
- [ ] 是否验证开发备注/逻辑说明入口可打开、可关闭，内容与 PRD/字段清单/规则表口径一致。

验证记录必须包含：

| 验证路径 | 测试数据/前置状态 | 预期结果 | 实际结果 | 数据/状态变化 | 证据 | 是否通过 | 未覆盖/备注 |
|---|---|---|---|---|---|---|---|

### 3.1 真实结果判定规则

- 只打开页面，不等于数据绑定通过；只点击按钮，不等于保存、提交或状态流转通过。
- 出现Toast但数据/状态未变化，不得判定业务结果通过。
- 返回列表后必须核对新增行、字段值或状态，不得只确认“已返回”。
- 文档写“必填、精确匹配、权限继承、自动带出、写入台账”时，HTML必须有对应验证证据；否则标记“未实现/未覆盖”。
- 产品确认原型可以不实现完整持久化，但必须明确写“仅验证页面结构，不验证数据落表”。

### 3.2 文件安全与版本保护

- [ ] 修改前是否保留可恢复的上一有效版本。
- [ ] 写入后文件大小是否大于0字节。
- [ ] HTML是否能在浏览器打开并显示非空主内容。
- [ ] 是否检查控制台阻断性错误。
- [ ] 是否确认当前有效版本唯一。
- [ ] 是否检查PRD、页面说明、HTML、开发备注中的字段/状态/权限/待确认项一致。

### 3.3 固定视口检查

- [ ] 桌面1440×900。
- [ ] 桌面1180×800或项目约定的最小桌面宽度。
- [ ] 移动390×844（仅移动端/响应式项目）。
- [ ] 宽表可完整查看或提供明确横向滚动。
- [ ] 弹窗、抽屉、遮罩不溢出、不遮挡必要操作。
- [ ] 移动端没有评审壳挤压真实页面。

### 3.4 兼容、数据与业务验收边界

- [ ] 已明确支持的浏览器、版本、设备和不支持范围，并在目标环境实测。
- [ ] 键盘焦点、表单标签、错误提示和颜色对比等基础无障碍能力已检查，或明确不适用及原因。
- [ ] 测试账号和数据为虚构/脱敏数据；无真实个人信息、生产凭据，且有清理方式。
- [ ] 内部HTML QA与业务UAT分别记录，未用产品经理主观确认替代全量功能测试。
- [ ] 业务UAT覆盖核心业务场景、规则口径和角色结果，结论及确认人可追溯。
- [ ] 遗留P2、未覆盖项、发布依赖和风险接受人已明确。
- [ ] 若进入真实上线，已明确监控、灰度、回滚/恢复和交接负责人；纯原型明确标记不适用。

## 4. 一票否决项

出现以下任一情况，不能称为完成：

- 未读取数智工厂基线就生成数智工厂原型。
- 未确认设计规范来源就生成最终风格 HTML 原型。
- 使用现有系统链接反推规范但未给产品经理确认，就直接作为最终基线。
- 使用现有系统链接反推规范但未按 09 完整性清单覆盖系统壳、页面类型、组件、视觉、交互和 HTML 适配规则。
- 使用产品提供规范文档但未提炼成项目基线、未处理冲突、未给产品经理确认，就直接生成最终风格 HTML。
- 使用产品提供规范文档但未按 10 完整性清单覆盖系统壳、页面层级、组件、视觉、交互和 HTML 适配规则。
- 未确认页面结构和交互矩阵就生成开发实现原型。
- 开发实现 HTML 原型缺少开发备注/逻辑说明/字段说明入口，或备注内容与 PRD 冲突却未说明。
- 原型是演示型、讲解型、汇报型，却声称可交付开发。
- 承载系统的菜单、导航或页面层级错误，把流程内页面错误做成一级入口。
