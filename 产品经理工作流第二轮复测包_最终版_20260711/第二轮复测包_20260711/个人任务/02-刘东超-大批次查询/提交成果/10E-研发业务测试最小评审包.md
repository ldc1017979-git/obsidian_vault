# 大批次查询功能｜研发、业务、测试最小评审包

> 目的：关闭PRD V0.2的5个P1。产品经理不需要回答数据库、接口或代码实现。

## 一、研发/数据负责人确认

请基于现有数智工厂系统提供结论或可追溯证据：

1. 29类表单分别通过哪个现有数据对象与“大批次号”关联；是否存在无法关联或口径不同的类型。
2. 每类能否提供公共字段：表单名称、大批次号、产线、班组、班次、业务日期、提交时间、提交人、表单状态、详情标识。
3. 字段缺失时返回什么；业务日期和状态分别映射哪个现有字段。
4. 单类查询超时/失败能否被识别，能否在保留其他成功结果时执行整次重新查询。
5. 单个大批次记录总数的典型值、P95或常见峰值、历史最大值；29类全部展开不分页是否可承载。
6. 建议响应时间、超时阈值；若超量，研发建议的用户可感知降级结果。

## 二、权限/系统管理员确认

1. “大批次查询”菜单/页面权限标识和无权限入口规则。
2. 29类表单详情页面的真实路由或跳转标识。
3. 29类表单查看权限标识。
4. 查询结果是否还受组织、工厂、产线等数据范围约束。
5. 无详情权限时，服务端能否阻止直达越权，不仅依赖按钮禁用。
6. 提交人等字段是否需要隐藏或脱敏。

## 三、业务代表确认

1. 29类表单名称是否为当前系统标准名称。
2. 10个公共列表字段在29类中是否都有业务意义；没有时应显示“—”、空白还是不适用。
3. 各类型“业务日期”字段的业务含义是否一致。
4. 各类型状态原样展示是否会产生歧义。

## 四、测试负责人确认

1. AC01-AC19是否具备可执行的测试数据和环境。
2. 能否准备：有/无查询权限、有/无各类详情权限、空结果、部分失败、整体失败、日期边界、多产线、29类覆盖的数据。
3. 能否准备典型值、峰值和超量数据，验证全部展开、不分页。
4. 目标浏览器、分辨率和基础无障碍范围。

## 五、最小回传格式

每项可以回复：

- 已确认：结论 + 证据位置/截图。
- 有差异：实际口径 + 影响范围。
- 暂无法确认：负责人 + 预计确认阶段。
- 不适用：原因。

任何没有证据的项目继续标记“未覆盖”，不视为通过。
