# 01-仓库目录结构规范

## 1. 顶层目录原则

顶层目录只放项目级入口，不放零散过程文件。

推荐结构：

```text
project-name/
├─ README.md
├─ docs/
├─ src/
├─ assets/
├─ data/
├─ scripts/
├─ tests/
├─ .gitignore
└─ CHANGELOG.md
```

## 2. 目录用途

| 目录或文件 | 用途 |
|---|---|
| `README.md` | 项目入口，说明项目是什么、怎么运行、怎么使用 |
| `docs/` | 产品说明、接口文档、操作手册、方案文档 |
| `src/` | 正式源代码 |
| `assets/` | 图片、图标、截图、演示素材 |
| `data/` | 可公开的样例数据、测试数据、字典数据 |
| `scripts/` | 自动化脚本、一次性处理脚本 |
| `tests/` | 测试用例 |
| `.gitignore` | 声明哪些文件不进入 Git |
| `CHANGELOG.md` | 记录版本变化 |

## 3. 文件命名规范

推荐：

```text
lowercase-with-hyphen.md
feature-name.ts
user-import-template.xlsx
2026-06-22-release-note.md
```

避免：

```text
新建文档.md
最终版.md
最终版2.md
final-final-v3.md
临时文件不要删.md
```

## 4. 文档命名建议

```text
docs/
├─ product-requirements.md
├─ api-reference.md
├─ deployment-guide.md
├─ user-guide.md
└─ release-notes/
```

中文团队也可以用中文文件名，但要保持稳定、明确、少改名。

## 5. 什么不应该放进仓库

- 密码、Token、私钥、Cookie、账号配置
- `.env` 真实环境变量文件
- `node_modules/`
- 构建产物，例如 `dist/`、`build/`
- 系统缓存，例如 `.DS_Store`
- 临时导出文件
- 没有必要追踪的大视频、大压缩包、大模型文件
