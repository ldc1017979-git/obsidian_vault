# 03-协作与权限规范

## 1. 角色分工

| 角色 | 权限建议 | 主要职责 |
|---|---|---|
| Owner | 管理员 | 管仓库、权限、分支保护、发版 |
| Maintainer | 写入权限 | 审核 PR、维护主分支 |
| Contributor | 分支提交 | 开发、修复、补文档 |
| Viewer | 只读 | 查看代码和文档 |

## 2. 主分支规则

`main` 或 `master` 分支应该保持可用。

建议：

- 禁止直接向主分支提交高风险改动
- 重要仓库开启 Pull Request 审核
- 合并前至少一人检查
- 发版前打 Tag

## 3. Pull Request 应该说明什么

```text
本次改了什么
为什么要改
影响哪些模块
如何验证
是否有风险
是否需要后续事项
```

## 4. 文件归属

多人协作时，建议为关键目录指定负责人：

```text
docs/       产品或项目负责人
src/        开发负责人
assets/     设计或运营负责人
data/       数据负责人
scripts/    技术负责人
```

## 5. 删除文件规则

删除文件前先确认：

- 是否仍被代码引用
- 是否仍被文档链接
- 是否是历史资料
- 是否应该迁移到 `archive/`
- 是否需要在 PR 里说明删除原因
