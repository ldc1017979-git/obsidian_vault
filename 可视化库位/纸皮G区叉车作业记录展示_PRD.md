# 纸皮 G 区叉车作业记录展示 PRD

> 文档状态：需求初稿  
> 产品模块：可视化库位 - 库区管理  
> 目标页面：纸皮 G 区  
> 适用终端：PC 端  
> 方案方向：作业记录时间轴  
> 更新时间：2026-07-20

---

## 1. 项目背景

当前“库区管理 - 纸皮 G 区”页面主要展示库位占用情况及库区统计信息。现场叉车员在平板端完成作业后，会选择一个或多个对应库位，填写叉车员名称并上传货物照片。

PC 端目前缺少与具体库位关联的作业记录展示区域，管理人员无法在库位页面直接确认该库位最近由谁操作、何时完成以及货物现场情况。

本次需求在纸皮 G 区页面右侧增加“作业记录”时间轴。用户点击左侧库位后，右侧区域展示该库位最近 3 条叉车作业记录。

## 2. 产品目标

1. 让管理人员点击库位后，可以快速查看该库位最近的叉车作业情况。
2. 清晰展示叉车员名称、操作完成时间和 1～3 张货物照片。
3. 支持照片切换与放大查看，便于核对货物现场状态。
4. 仅保留并展示每个库位最近 3 条记录，避免历史数据持续累积。
5. 保持现有库位管理页面的主要结构和操作方式不变。

## 3. 本期需求范围

### 3.1 包含范围

- PC 端“库区管理 - 纸皮 G 区”页面。
- 用户点击单个库位后的右侧作业记录展示。
- 最近 3 条作业记录的时间轴展示。
- 叉车员名称、操作完成时间、货物照片展示。
- 单条记录支持 1～3 张照片。
- 多图切换、缩略图选择和大图预览。
- 无数据、加载中、加载失败等页面状态。
- 后端仅保留最近 3 条记录的数据规则。

### 3.2 不包含范围

- 平板端的填写、上传和提交界面。
- PC 端新增、修改或删除作业记录。
- PC 端上传照片。
- 超过 3 条记录的历史查询。
- 照片下载、打印、批量导出。
- 用户权限和角色体系调整。

## 4. 用户与使用场景

### 4.1 目标用户

- 仓库管理人员
- 现场调度人员
- 需要核对库位货物状态的业务人员

### 4.2 核心使用场景

管理人员进入“库区管理 - 纸皮 G 区”页面，点击某个库位。系统在右侧加载该库位最近 3 条作业记录。管理人员可以查看叉车员、完成时间和货物照片，并通过点击照片打开大图进行核对。

## 5. 页面位置与整体布局

### 5.1 页面入口

`库区管理 → 纸皮 G 区`

### 5.2 展示位置

作业记录展示在现有页面右侧区域，位于库位使用率、库位统计及操作按钮的下方。该区域仅用于查看，不提供编辑入口。

### 5.3 布局原则

- 不遮挡左侧库位图。
- 保留现有顶部导航、库区标签、查询条件和库位统计模块。
- 右侧面板使用独立纵向滚动，不带动整个页面滚动。
- 时间轴按完成时间倒序排列，最新记录始终位于顶部。
- 默认最多展示 3 条，不提供“加载更多”。

## 7. 交互流程

### 7.1 查看库位记录

1. 用户进入纸皮 G 区页面。
2. 页面尚未选中库位时，右侧作业记录区域显示引导文案。
3. 用户点击左侧任意库位。
4. 被点击库位显示现有系统规定的选中状态。
5. 右侧区域进入加载状态。
6. 系统根据库位唯一标识查询该库位最近 3 条记录。
7. 查询成功后，按完成时间从新到旧展示记录。
8. 用户切换点击其他库位时，右侧内容同步切换。

### 7.2 查看照片

1. 每条记录至少展示 1 张、最多展示 3 张照片缩略图。
2. 用户点击任意缩略图后，打开照片预览弹层。
3. 弹层默认展示用户所点击的照片。
4. 当记录包含多张照片时，弹层提供上一张、下一张按钮。
5. 弹层显示当前图片序号，例如“2 / 3”。
6. 用户可点击关闭按钮、遮罩空白区域或按 `Esc` 键关闭弹层。
7. 查看照片不会改变记录顺序和当前库位选择状态。

## 8. 功能需求

### 8.1 当前库位信息

右侧作业记录区域顶部显示当前选中的库位名称或编号。

示例：

```text
当前库位：1-1
```

切换库位后，该字段应立即同步更新，不得继续显示上一个库位的信息。

### 8.2 作业记录时间轴

- 最多显示 3 条记录。
- 按操作完成时间倒序排列。
- 第一条为最新记录，第三条为最早记录。
- 每条记录应作为独立时间轴节点展示。
- 节点之间使用竖向连接线体现时间顺序。
- 不显示记录编辑、删除、上传等操作按钮。

### 8.3 单条记录字段

| 字段 | 是否必填 | 展示规则 |
|---|---:|---|
| 记录 ID | 是 | 系统内部使用，前端不直接展示 |
| 库位 ID | 是 | 用于查询和关联记录 |
| 库位名称/编号 | 是 | 在面板顶部展示 |
| 叉车员名称 | 是 | 完整展示，过长时换行或省略并提供悬停提示 |
| 操作完成时间 | 是 | 格式为 `YYYY-MM-DD HH:mm:ss` |
| 货物照片 | 是 | 每条最少 1 张、最多 3 张 |

### 8.4 照片展示

- 缩略图采用统一尺寸和圆角样式。
- 图片使用等比例裁切，避免图片变形。
- 鼠标移入时显示可点击状态。
- 图片加载失败时显示统一占位图和“图片加载失败”提示。
- 多张照片按上传顺序从左至右排列。
- 图片原图在预览弹层中等比例展示，不拉伸。
- 大图超出屏幕时，应自动缩放到可视区域内。

## 9. 数据规则

### 9.1 数据关联

- 每条作业记录至少关联一个库位。
- 平板端一次作业可选择一个或多个库位。
- 当一条记录关联多个库位时，该记录应分别出现在所有关联库位的最近记录中。
- PC 端根据当前选中的库位查询关联记录。

### 9.2 最近 3 条保留规则

系统对每个库位仅保留最近 3 条作业记录。

规则如下：

1. 当前库位记录少于 3 条时，新记录正常写入。
2. 当前库位已有 3 条记录时，新产生第 4 条记录。
3. 第 4 条记录成功写入后，系统删除完成时间最早的第 1 条记录。
4. 最终数据库中该库位仍保留 3 条记录。
5. PC 端重新查询后展示新的最近 3 条记录。

示例：

| 写入前 | 新写入 | 写入后保留 |
|---|---|---|
| 记录 A、记录 B、记录 C | 记录 D | 记录 B、记录 C、记录 D |

其中 A 为最早记录，D 为最新记录。

### 9.3 多库位记录的删除约束

当一条作业记录同时关联多个库位时，应以“库位与记录的关联关系”为单位执行最近 3 条规则。

例如，一条记录同时关联库位 A 和库位 B：

- 如果该记录在库位 A 中已成为第 4 条以外的历史记录，仅移除其与库位 A 的关联。
- 如果该记录在库位 B 中仍属于最近 3 条，则库位 B 仍需正常展示。
- 只有当该记录不再关联任何库位时，才可清理记录主体及相关照片资源。

该规则用于避免清理某一库位的旧数据时，误删其他库位仍在使用的记录。

### 9.4 时间一致性

- “上传时间”和“操作完成时间”在本期视为同一个字段。
- 时间由服务端统一记录或校准，避免不同平板设备时间不一致。
- 排序和数据淘汰均以服务端保存的操作完成时间为准。
- 时间相同时，以记录创建序号或记录 ID 倒序作为第二排序条件。

## 10. 页面状态

### 10.1 未选择库位

展示内容：

```text
作业记录
请点击左侧库位查看作业记录
```

### 10.2 加载中

- 显示 2～3 条骨架屏。
- 加载期间保留当前库位名称。
- 不短暂显示上一个库位的旧记录。

### 10.3 无记录

展示内容：

```text
当前库位暂无作业记录
```

同时显示简洁的图片或文件空状态图标。

### 10.4 加载失败

展示内容：

```text
作业记录加载失败
[重新加载]
```

点击“重新加载”仅重新请求当前库位数据。

### 10.5 图片加载失败

- 单张图片失败不影响其他字段及其他照片展示。
- 失败位置显示占位图。
- 用户可以重新打开或刷新页面后再次尝试加载。

## 11. 视觉规范

### 11.1 整体风格

- 延续现有系统的蓝色主色和浅灰色边框。
- 面板背景使用白色。
- 时间轴节点使用系统主蓝色。
- 最新一条记录可使用浅蓝色背景或“最新”标签突出。
- 旧记录保持白色背景，降低视觉权重。

### 11.2 信息层级

1. 当前库位
2. 最新记录
3. 操作完成时间
4. 叉车员名称
5. 货物照片

### 11.3 建议尺寸

- 右侧记录面板建议宽度：`280px～340px`。
- 面板内边距：`12px～16px`。
- 照片缩略图建议尺寸：`72px × 56px`。
- 缩略图间距：`6px～8px`。
- 时间轴节点直径：`8px～10px`。
- 记录卡片圆角：`4px～6px`。

若现有右侧栏宽度不足，应优先适当加宽右侧栏，不建议继续压缩图片和文字。

## 12. 接口建议

### 12.1 查询最近作业记录

请求示例：

```http
GET /api/storage-zones/{zoneId}/locations/{locationId}/forklift-records?limit=3
```

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "locationId": "G-01-01",
    "locationName": "1-1",
    "records": [
      {
        "recordId": "REC-20260720-001",
        "forkliftOperatorName": "张师傅",
        "completedAt": "2026-07-20 10:21:35",
        "photos": [
          {
            "photoId": "P-001",
            "thumbnailUrl": "https://example.com/photo-1-thumb.jpg",
            "originalUrl": "https://example.com/photo-1.jpg",
            "sort": 1
          }
        ]
      }
    ]
  }
}
```

### 12.2 接口要求

- `records` 最多返回 3 条。
- `records` 必须按 `completedAt` 倒序返回。
- `photos` 最少 1 条、最多 3 条。
- 照片应同时提供缩略图地址和原图地址。
- 无记录时返回空数组，不使用 `null`。
- 接口应校验当前用户是否有权查看该库区。

## 13. 非功能要求

### 13.1 性能

- 点击库位后，正常网络环境下记录区域应在 2 秒内完成展示。
- 缩略图应优先加载，原图在用户打开预览时加载。
- 快速连续切换库位时，仅展示最后一次点击库位的请求结果。
- 应取消无效请求或通过请求标识避免旧请求覆盖新请求。

### 13.2 兼容性

- 适配 PC 端主流 Chromium 内核浏览器。
- 建议最低分辨率：`1366 × 768`。
- 在 `1920 × 1080` 分辨率下应完整展示右侧面板。

### 13.3 安全性

- 照片访问地址应受系统权限控制。
- 前端不得在页面源码或请求参数中暴露账号、密码等敏感信息。
- 用户退出登录后，照片链接不应继续允许未授权访问。
- 页面展示叉车员名称时，应遵循系统现有人员信息权限规则。

## 14. 埋点与日志建议

本期可选记录以下行为：

- 用户点击库位并成功加载作业记录。
- 用户打开照片预览。
- 作业记录接口加载失败。
- 照片资源加载失败。
- 后端执行第 4 条写入及最早记录清理。

日志需要包含库区 ID、库位 ID、记录 ID、操作时间和结果，不记录用户密码。

## 15. 验收标准

### 15.1 核心功能验收

- [ ] 进入纸皮 G 区后，未选择库位时显示操作引导。
- [ ] 点击任意库位后，右侧显示该库位名称。
- [ ] 右侧最多展示该库位最近 3 条作业记录。
- [ ] 3 条记录按操作完成时间从新到旧排列。
- [ ] 每条记录正确展示叉车员名称和操作完成时间。
- [ ] 每条记录可展示 1～3 张货物照片。
- [ ] 点击照片能够打开大图预览。
- [ ] 多张照片可在预览弹层中前后切换。
- [ ] 切换库位后，右侧记录同步更新。
- [ ] 右侧区域不出现新增、编辑或删除入口。

### 15.2 数据规则验收

- [ ] 库位少于 3 条记录时，新记录能够正常写入。
- [ ] 库位已有 3 条记录时，写入第 4 条后删除最早一条。
- [ ] 写入完成后，数据库和 PC 端均只保留最近 3 条。
- [ ] 多库位共用记录时，清理一个库位的旧关联不会影响其他库位展示。
- [ ] 时间相同时，记录顺序仍保持稳定。

### 15.3 异常状态验收

- [ ] 当前库位无记录时显示空状态。
- [ ] 接口请求失败时显示错误信息和重新加载按钮。
- [ ] 单张照片加载失败时不影响其他记录展示。
- [ ] 快速点击多个库位时，不出现旧库位数据覆盖新库位数据的问题。
