# 数据分析方法与结论规范

## 1. 先判断分析类型

产品经理拿到需求后，先不要问“做什么图”，而是判断它属于哪类分析：

| 分析类型 | 典型问题 | 主要输出 |
|---|---|---|
| 监控 | 业务现在是否正常 | KPI、趋势、异常预警 |
| 诊断 | 为什么变好或变差 | 拆解路径、影响因素、对比 |
| 对比 | 哪个区域/渠道/商品/人群更好 | 排名、分层、差异原因 |
| 复盘 | 活动或项目效果如何 | 前后对比、目标达成、沉淀动作 |
| 留存/复购 | 用户是否留下来 | T0、窗口、转移矩阵、运营清单 |
| 动销/门店 | 哪些门店有风险或机会 | 门店层级、热力图、下钻明细 |
| 预警 | 哪些对象需要立即处理 | 规则、等级、责任人、处理清单 |

如果分析类型不清楚，后续指标和页面都会跑偏。

## 2. 每类分析必须确认的问题

### 2.1 监控类

- 监控对象是什么：销售、库存、订单、门店、用户、履约、活动。
- 正常范围是什么：目标值、历史均值、阈值、同比/环比。
- 多久更新一次：实时、小时、天、周、月。
- 异常后谁处理，处理什么。

### 2.2 诊断类

- 变差或变好的指标是哪一个。
- 和谁比较：目标、同期、上期、活动前后、其他区域/渠道/商品。
- 是否有影响因素字段：价格、库存、铺货、活动、渠道、区域、人群、商品。
- 是否需要输出原因排序和行动建议。

### 2.3 对比类

- 对比对象是什么：区域、渠道、门店、SKU、人群、业务员。
- 基数是否可比：样本量太小的对象不能直接排名。
- 是否需要Top N和尾部清单。
- 是否需要控制时间、品类、区域等条件。

### 2.4 复盘类

- 复盘周期和对照周期是什么。
- 目标是什么：拉新、转化、动销、留存、收入、效率。
- 是否有活动日历、上线时间、政策变化、异常事件。
- 是否有参与对象和未参与对象。

### 2.5 留存/复购类

- 第一次行为是什么。
- 第二次行为是什么。
- 同一天重复行为是否算复购。
- 观察窗口和截止日期是什么。
- 是否排除非目标身份、测试数据、异常行为。

### 2.6 动销/门店类

- 门店唯一标识是什么。
- 门店和组织层级如何对应。
- 动销行为如何定义。
- 0值门店、无行为门店是否单独分析。
- 下钻明细要给谁处理。

## 3. 字段是否足够的判断规则

| 缺少字段 | 影响 |
|---|---|
| 没有唯一ID | 不能做去重、留存、复购、对象级下钻 |
| 没有时间字段 | 不能做趋势、前后对比、生命周期 |
| 没有维度字段 | 不能拆区域、渠道、商品、门店、人群 |
| 没有状态字段 | 不能排除取消、退款、无效、异常数据 |
| 没有金额/数量 | 不能分析收入、件数、效率、成本、ROI |
| 没有目标或基准 | 只能描述现状，不能判断好坏 |
| 没有活动/政策时间 | 很难解释波动原因 |

当字段不足时，产品经理必须让Codex明确输出“能做什么、不能做什么、需要补什么”。

## 4. 结论输出规范

数据分析结论必须包含四层：

```text
发现
-> 证据
-> 判断
-> 动作
```

| 层级 | 要求 |
|---|---|
| 发现 | 用一句话说清楚发生了什么 |
| 证据 | 引用具体指标、时间、对象、变化幅度 |
| 判断 | 说明可能原因或业务含义 |
| 动作 | 给出下一步处理、跟进、验证或开发建议 |

不要只写“有所提升”“表现较差”“建议关注”。必须写清楚哪个对象、差多少、为什么重要、下一步怎么做。

## 5. 不能下结论时怎么写

当数据不足或口径未确认时，不能强行给结论。应按下面方式表达：

```text
当前只能判断：
- ...

当前不能判断：
- ...

原因：
- 缺少...

建议补充：
- ...
```

这比输出一个看似完整但不可信的结论更重要。

## 6. 看板中的AI结论要求

AI结论区必须来自已计算数据，至少包含：

- 关键异常：哪个指标、哪个对象、在哪个时间异常。
- 主要贡献：变化主要来自哪些区域、渠道、商品、门店或人群。
- 风险对象：需要运营跟进的明细对象。
- 建议动作：谁处理、处理什么、优先级是什么。
- 待验证假设：哪些原因还需要补数据确认。

AI结论不应替代口径和数据验证，也不能使用没有数据支撑的主观判断。

## 7. 数据分析交付检查

交付前逐项确认：

| 检查项 | 要求 |
|---|---|
| 业务问题 | 已明确，不只是“做个看板” |
| 分析类型 | 已判断监控、诊断、对比、复盘等类型 |
| 数据粒度 | 已说明一行数据代表什么 |
| 指标口径 | 每个核心指标有分子、分母、窗口、去重、排除 |
| 数据验证 | 样本量、日期、空值、重复、分桶、分子分母已检查 |
| 输出数据集 | KPI、趋势、结构、分桶、明细可追溯 |
| 结论 | 每条结论有发现、证据、判断、动作 |
| 限制 | 已说明不能判断的内容和原因 |
| 看板 | 页面数据、筛选、下钻、口径说明、AI结论可用 |
| 开发 | 数据表、字段、接口、交互、验收标准清楚 |

## 8. 给Codex的分析提示词

```text
请按数据分析方法与结论规范处理这个需求。

先判断分析类型，再判断字段和数据粒度是否足够。
不要直接给图表方案。

请输出：
1. 分析类型判断
2. 业务问题定义
3. 当前字段和数据粒度判断
4. 能分析什么
5. 不能分析什么
6. 必须补充或确认的信息
7. 指标口径草案
8. 数据验证方案
9. 结论输出框架：发现、证据、判断、动作
10. 看板和开发交付建议
```
