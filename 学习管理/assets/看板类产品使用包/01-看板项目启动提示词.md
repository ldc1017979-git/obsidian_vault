# 看板项目启动提示词

## 0. 只有一句话时

如果产品经理只说：

```text
我现在要做数据分析，我应该怎么做？
```

请不要直接生成图表、看板或PRD。

请先回答：

```text
可以。我们先不要直接做图表或看板。

我会先帮你确认业务问题、使用人、决策动作、数据来源、字段粒度和最终交付。
本流程默认目标是开发可执行交付：数据分析方案、指标口径字典、数据验证报告、数据分析结论、HTML看板和开发交付说明。
你先回答5个问题，不确定的地方可以写“不确定”：

1. 你这次想分析什么业务问题？
2. 这个分析给谁看？看完后要做什么动作？
3. 你现在有什么数据或资料？
4. 分析的时间范围是什么？
5. 最终希望交付什么？

你回答后，我会继续输出：
1. 资料合格性判定：A可交付、B可设计不可下结论、C只能继续澄清、D不可推进
2. 分析类型判断
3. 当前资料能分析什么
4. 当前不能分析什么
5. 必须补充的信息
6. 下一步执行计划
```

## 1. 一句话需求启动

```text
请按看板类产品工作流启动项目。

看板名称：
一句话需求：
看板使用人：
看完后要做什么动作：
时间范围：
数据来源：
已有字段或样本：
目标交付：指标口径字典+数据验证报告+看板结构说明+单文件HTML看板
默认交付：数据分析方案+指标口径字典+数据验证报告+数据分析结论+输出数据集设计+单文件HTML看板+浏览器验证记录+开发交付说明

请先不要画图表，也不要直接生成HTML。

请先输出：
1. 资料合格性判定：A可交付、B可设计不可下结论、C只能继续澄清、D不可推进。
2. 这个需求属于监控、诊断、复盘、对比、预警、运营清单中的哪类。
3. 当前业务问题是什么。
4. 可能的分析对象和数据粒度。
5. 已有资料能支持哪些分析。
6. 当前不能做哪些分析。
7. 后续结论应按“发现、证据、判断、动作”怎么输出。
8. 第一轮必须确认的3-5个问题。
9. 下一步执行计划。
```

## 2. 字段表或数据样本输入后

```text
我已经提供字段清单/数据样本。

请先做字段盘点，不要直接设计看板。

请输出：
1. 字段分类：主键、时间、行为、金额、数量、维度、标签、状态、关系。
2. 判断每一行数据代表什么粒度。
3. 当前能分析什么。
4. 当前不能分析什么。
5. 推荐指标和每个指标的口径草案。
6. 可支持的分析类型和不可支持的分析类型。
7. 缺失字段和待确认问题。
```

## 3. 生成HTML看板前检查

```text
请检查当前资料是否足以生成HTML看板。

请输出：
1. 已确认的业务问题。
2. 已确认的指标口径。
3. 已验证的数据来源。
4. 已准备的输出数据集。
5. 仍缺失的信息。
6. 数据分析结论是否具备发现、证据、判断、动作。
7. 是否可以进入HTML看板生成。
```

## 4. 生成HTML看板

```text
请基于已确认的指标口径、数据验证报告和输出数据集，生成单文件HTML看板。

要求：
1. 是真正的数据分析看板，不是展示页。
2. 包含全局筛选、KPI总览、趋势、结构、对比、明细下钻和AI结论摘要。
3. 关键指标必须有口径说明。
4. 清楚标记数据来源、截止时间、正式/模拟状态。
5. AI结论必须基于计算数据，不写泛泛建议。
6. 页面专业、紧凑、适合BI使用。
7. 完成后进行浏览器验证，检查数据非空、布局、筛选和交互。
```
