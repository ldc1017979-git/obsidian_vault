# 看板结构与交互规范

## 1. 默认看板结构

```text
全局筛选
-> 数据状态
-> KPI总览
-> AI结论摘要
-> 趋势分析
-> 结构分析
-> 漏斗/生命周期/分层
-> 对比分析
-> 明细下钻
-> 数据质量和口径说明
-> 指标释义
```

## 2. 必须有的数据状态区

看板必须显示：

- 数据来源
- 数据截止日期
- 正式/模拟状态
- 样本量
- 关键排除规则
- 口径版本

## 3. 交互要求

| 交互 | 要求 |
|---|---|
| 全局筛选 | 时间、区域、渠道、产品、门店、用户标签等 |
| KPI卡片 | 支持口径说明 |
| 趋势图 | 标记活动、异常、上线等时期 |
| 结构图 | 维度过多时用Top N+明细表 |
| 热力图 | 每个对象只能归属一个格子 |
| 明细下钻 | 支持从汇总跳到明细清单 |
| 导出 | 明细表适合运营跟进 |
| AI结论 | 基于计算结果，指出异常和动作 |

## 4. 模块自解释要求

每个核心模块必须让业务用户看懂三件事：

- 这个模块看什么。
- 当前数据说明什么。
- 业务应该怎么用。

不要只放图表标题。结论必须引用具体指标、对象、时间和变化幅度。

## 5. BI视觉原则

- 专业、紧凑、可扫描。
- 不做营销式大图。
- 指标卡少而关键。
- 图表标签不拥挤，必要时用表格承接。
- 大数字加千分位。
- 指标说明用问号或说明弹层。
- 结论区必须引用具体数据。
- 颜色必须有业务含义，例如正常、风险、预警、样本小、增长、下降。
- 图表必须显示单位，长标签和大数字不能遮挡。
- 维度很多时，用Top N、筛选、表格或下钻，不要硬塞一张图。
