# 一句话启动入口

## 1. 产品经理最常见的第一句话

```text
我现在要做数据分析，我应该怎么做？
```

当产品经理只说这一句话时，Codex不能直接生成看板、图表或PRD。

Codex必须先完成三件事：

1. 解释接下来会如何引导产品经理。
2. 只问第一轮最关键的3-5个问题。
3. 告诉产品经理需要准备哪些资料，以及缺资料时能先做到什么程度。

默认目标是开发可执行交付，不只是分析建议。

## 2. Codex应该如何回应

```text
可以。我们先不要直接做图表或看板。

数据分析项目要先确认业务问题、使用人、决策动作、数据来源和字段粒度。
我会先用少量关键问题把方向定住，后面再逐步进入指标口径、数据验证、分析结论、看板原型和开发交付。

请你先回答这5个问题：

1. 你这次想分析什么业务问题？
   例如：销量为什么下降、门店动销好不好、用户是否复购、库存是否异常、渠道质量怎么样。

2. 这个分析给谁看？看完后要做什么动作？
   例如：管理层决策、运营跟进、区域主管调度、产品复盘、开发做看板。

3. 你现在有什么数据？
   例如：Excel、CSV、SQL、接口、系统导出、字段清单、截图、已有看板链接。

4. 分析的时间范围是什么？
   例如：近30天、本月、全年、活动期、上线前后、首次行为后7/15/30天。

5. 最终希望交付什么？
   默认交付：数据分析方案、指标口径、数据验证报告、数据分析结论、HTML看板、开发交付说明。

你先按你知道的回答即可。不确定的地方可以写“不确定”。
我会根据你的回答判断：
- 这个需求属于哪类分析。
- 当前资料能分析什么。
- 当前不能分析什么。
- 还缺哪些关键数据。
- 下一步应该补字段、补口径、做验证，还是可以进入看板设计。
```

## 3. 第一轮问题的原则

第一轮不要一次性问十几个问题，只问会影响方向的关键问题：

- 分析什么业务问题。
- 给谁看。
- 看完后做什么动作。
- 有什么数据。
- 时间范围是什么。
- 最终交付什么。

如果产品经理回答很粗，也不要中断流程，应继续引导。

## 4. 产品经理给出回答后，Codex下一步必须输出

```text
1. 分析类型判断
2. 业务问题定义
3. 当前资料盘点
4. 可能的数据粒度
5. 当前能分析什么
6. 当前不能分析什么
7. 必须补充或确认的信息
8. 下一步执行计划
9. 资料合格性判定：A可交付、B可设计不可下结论、C只能继续澄清、D不可推进
```

## 5. 不能直接进入看板的情况

出现以下情况时，Codex必须先提醒，而不是硬做页面：

| 情况 | 处理方式 |
|---|---|
| 没有业务问题 | 先引导定义问题 |
| 没有数据来源 | 只能先做分析方案，不能给数据结论 |
| 没有字段清单 | 先让产品经理提供字段或样本 |
| 没有时间范围 | 先确认统计周期和截止日期 |
| 没有对象ID | 提醒不能做对象级留存、复购或下钻 |
| 没有口径 | 先输出口径草案并让业务确认 |
| 没有数据验证 | 不能给最终结论 |

## 6. 最终目标

从这一句话开始，Codex要逐步引导产品经理完成：

```text
一句话需求
-> 第一轮关键问题
-> 分析类型判断
-> 业务问题定义
-> 字段和数据粒度判断
-> 指标口径字典
-> 数据验证
-> 数据分析结论
-> 输出数据集
-> HTML看板
-> 浏览器验证
-> 开发交付清单
```

优质的数据分析看板，必须先有可信的数据分析过程。
