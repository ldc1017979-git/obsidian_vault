# 开始这里：产品经理只看这个

## 1. 你只需要做一件事

先确认当前Codex项目里已经有这个文件夹：

```text
看板类产品使用包
```

打开Codex后，直接复制这句话发送：

```text
我现在要做数据分析，我应该怎么做？
```

不要先让Codex做图。
不要先让Codex做HTML。
不要先让Codex写PRD。

如果Codex没有主动按数据分析工作流提问，就补发这句话：

```text
请先读取当前项目里的“看板类产品使用包”，按里面的工作流引导我。
```

## 2. 接下来怎么做

Codex会问你几个问题，你按你知道的回答。

如果不确定，就直接写：

```text
不确定
```

Codex应该继续引导你，不应该要求你一次性准备完所有资料。

## 3. 你可能需要准备的资料

有多少给多少，不需要一开始全部准备齐。

- 你想分析的问题
- 这个分析给谁看
- 看完后要做什么动作
- 数据文件、字段表、Excel、CSV、SQL或接口
- 时间范围
- 已有系统截图、已有看板链接或知识库路径
- 你们已有的指标口径或业务规则

## 4. 本次默认要交付什么

默认目标不是只给建议，而是尽量交付到开发可执行：

- 数据分析方案
- 指标口径字典
- 数据验证报告
- 数据分析结论
- 输出数据集设计
- 单文件HTML看板
- 浏览器验证记录
- 开发交付说明

如果资料不够，Codex必须告诉你缺什么、影响什么、下一步补什么。

## 5. 你怎么判断这次试跑是否有效

看Codex有没有做到这些：

- 主动问你业务问题、使用人、动作、数据和时间范围。
- 判断当前资料是否足够。
- 说明现在能分析什么、不能分析什么。
- 先定义指标口径，再做看板。
- 先做数据验证，再给结论。
- 最后能输出开发看得懂的说明。

如果Codex一上来就直接做图或做页面，说明没有按工作流执行。
