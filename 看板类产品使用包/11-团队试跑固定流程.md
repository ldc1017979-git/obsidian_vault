# 团队试跑固定流程

## 1. 试跑目标

验证产品经理是否可以只用一句话启动数据分析项目，并在Codex引导下完成高质量看板交付。

本流程默认交付到开发可执行程度，不只做分析建议。

默认交付物：

- 数据分析方案
- 指标口径字典
- 数据验证报告
- 数据分析结论
- 输出数据集设计
- 单文件HTML看板
- 浏览器验证记录
- 开发交付说明

如果资料不足，Codex必须说明不足在哪里、会影响什么、需要补什么，不能硬做最终结论。

## 2. 产品经理统一第一句话

产品经理不需要先读完本文件。

给产品经理时，优先让他们打开：

```text
开始这里-产品经理只看这个.md
```

试跑前要确认：产品经理当前Codex项目里已经放入 `看板类产品使用包`。如果没有放入，Codex可能不知道本工作流。

产品经理在Codex里只发这一句话启动：

```text
我现在要做数据分析，我应该怎么做？
```

不要先贴模板，不要先要求做图，不要先要求生成HTML。

## 3. Codex必须先引导，而不是直接输出

Codex收到第一句话后，必须先问这5个问题：

```text
1. 你这次想分析什么业务问题？
2. 这个分析给谁看？看完后要做什么动作？
3. 你现在有什么数据或资料？
4. 分析的时间范围是什么？
5. 最终希望交付什么？
```

产品经理不知道的地方可以回答“不确定”。Codex应继续引导，不应停止。

## 4. Codex必须主动索要的资料

根据产品经理回答，Codex需要主动引导补充以下资料。

### 4.1 业务资料

| 资料 | 用途 |
|---|---|
| 业务问题 | 判断分析方向 |
| 使用人 | 决定看板层级和表达方式 |
| 看完后的动作 | 决定是否需要预警、下钻、导出、运营清单 |
| 时间范围 | 决定统计周期和观察窗口 |
| 业务范围 | 决定区域、渠道、门店、商品、人群边界 |
| 关键事件 | 判断活动、上线、政策、缺货等影响 |

### 4.2 数据资料

| 资料 | 用途 |
|---|---|
| 数据来源 | 判断Excel、CSV、SQL、API、系统导出 |
| 字段清单 | 判断能分析什么 |
| 数据样本 | 判断字段含义、格式、空值、异常 |
| 数据截止日期 | 判断结论时效 |
| 样本量 | 判断是否可信 |
| 正式/测试/模拟状态 | 防止用错数据 |
| 已有看板或系统截图 | 参考现有交互和指标表达 |
| 知识库路径或资料入口 | 读取业务背景、规则、历史口径 |

### 4.3 口径资料

| 资料 | 用途 |
|---|---|
| 指标定义 | 统一业务理解 |
| 去重规则 | 防止重复计数 |
| 排除规则 | 排除测试、内部、异常、取消、退款等 |
| 时间窗口 | 例如自然日、自然周、T0后7/15/30天 |
| 归因规则 | 首次、最近、事件、门店、渠道归因 |
| 分桶规则 | 留存窗口、动销层级、风险等级 |
| 组织层级 | 区域、分公司、办事处、门店等 |

## 5. 资料合格性判定

Codex拿到资料后，必须先判定是否合格。

| 等级 | 判定标准 | 可以做什么 |
|---|---|---|
| A：可交付 | 业务问题、字段、样本、时间范围、核心口径、数据来源基本齐全 | 可进入指标、数据验证、看板和开发交付 |
| B：可设计不可下结论 | 有业务问题和字段，但没有真实数据或样本不足 | 可做方案、口径、看板结构，不能给正式数据结论 |
| C：只能继续澄清 | 业务问题不清或没有字段/数据来源 | 只能继续问问题，不能设计最终看板 |
| D：不可推进 | 数据权限、业务范围或核心定义完全缺失 | 明确阻塞项，让产品经理补资料 |

Codex每次都要告诉产品经理当前属于A/B/C/D哪一级。

## 6. Codex拿到资料后的固定输出

产品经理补充资料后，Codex必须输出：

```text
1. 资料合格性判定：A/B/C/D
2. 业务问题定义
3. 分析类型判断
4. 字段盘点和数据粒度判断
5. 当前能分析什么
6. 当前不能分析什么
7. 缺失资料和影响
8. 指标口径草案
9. 数据验证方案
10. 下一步执行计划
```

## 7. 进入看板前的门槛

只有满足以下条件，才可以进入HTML看板：

- 业务问题明确。
- 使用人和动作明确。
- 数据来源明确。
- 字段粒度明确。
- 核心指标口径明确。
- 数据正式/测试/模拟状态明确。
- 数据验证方案明确。
- 输出数据集设计明确。

不满足时，Codex只能继续引导补资料或先做方案版。

## 8. 最终交付标准

最终输出必须包含：

```text
01-业务问题定义.md
02-指标口径字典.md
03-数据验证报告.md
04-数据分析结论.md
05-输出数据集说明.md
06-看板结构说明.md
07-HTML看板/index.html
08-浏览器验证记录.md
09-开发交付说明.md
```

开发交付说明至少写清：

- 页面模块
- 指标口径
- 数据表或接口需求
- 字段说明
- 筛选条件
- 下钻逻辑
- 导出逻辑
- 权限或数据范围
- 异常和空状态
- 验收标准

## 9. 试跑验收

试跑结束后，产品经理需要回答：

| 问题 | 说明 |
|---|---|
| Codex是否主动问出了必要信息 | 看引导能力 |
| Codex是否判断了资料是否合格 | 看风险控制 |
| Codex是否说明了不能分析什么 | 看边界意识 |
| 指标口径是否可被业务确认 | 看可落地性 |
| 核心指标是否写成指标契约 | 看口径稳定性 |
| 数据验证是否充分 | 看可信度 |
| 是否抽查原始数据到页面结果 | 看数据追溯 |
| 看板是否能指导动作 | 看业务价值 |
| 每个模块是否说明看什么、说明什么、怎么用 | 看业务可读性 |
| 开发交付是否清楚 | 看开发可执行性 |

## 10. 固定发给产品经理的话

```text
这次请按数据分析看板工作流试跑。

你进入Codex后，不要先贴模板，也不要直接让它做图或做HTML。
请只发这一句话：

“我现在要做数据分析，我应该怎么做？”

然后观察Codex是否能主动引导你补充业务问题、使用人、动作、数据来源、字段样本、时间范围、口径规则和交付目标。

你按它的问题逐步提供资料。
如果你不确定，就直接回答“不确定”，让它继续引导你。

本次默认目标不是只做分析建议，而是输出：
数据分析方案、指标口径字典、数据验证报告、数据分析结论、输出数据集设计、单文件HTML看板、浏览器验证记录、开发交付说明。

最后请记录：哪些问题它问到了，哪些没问到，哪些输出对开发还不够清楚。
```
