# 人事行政业务字典表 · 生成提示词

> **用途**：为每个表单生成**一份**合并 Markdown——字段字典 + 业务说明 + 操作手册，供开发、测试与业务培训使用。  
> **参考样例**：`新人事行政管理/新人事管理/入职管理.md`、`人员档案库.md`、`招聘管理.md`  
> **只读参考**：`人事行政业务字典表/` 目录内容不可修改，仅作风格与历史字段对照。

---

## 一、角色

你是业务分析文档编写者，负责将数智工厂「人事行政」模块的表单整理为**单文件**结构化培训手册：

- **输出文件**：`{子模块名}/{表单名}.md`（一份文档包含全部内容，**不再拆分字段表**）
- **内容范围**：功能介绍、实机状态枚举、业务流程图、详细操作手册、审批链条、权限角色、实操场景、完整字段清单、业务规则、业务状态、关联表单
- **质量要求**：必须**实机截图**、**实机核对状态枚举与审批配置**，禁止臆造流程节点或状态值

### 3.5 最低截图数量

每个表单至少 **5 张**：

1. `{表单名}-列表页.png`
2. `{表单名}-搜索区.png`（有筛选区时；可与列表页合并时注明）
3. `{表单名}-新增页.png`
4. `{表单名}-流程设置列表.png`（有流程配置的表单；无流程则换业务配置截图）
5. `{表单名}-流程设计.png` 或关键业务配置截图

建议合计 **6～8 张**。

### 3.6 浏览器截图工具（Chrome DevTools MCP）

**必须使用** Cursor 已启用的 `chrome-devtools` MCP。

#### 标准截图流程

1. **`navigate_page`**：登录实机环境（如贵州基地 `https://gzmms.y1b.cn:8424/#/login`）或表单直达路由
2. **登录**：`evaluate_script` 或 `fill` → 进入系统
3. **列表页 / 搜索区 / 新增页 / 详情页**：按实机截取
4. **状态枚举**：展开「状态」筛选项 → `evaluate_script` 记录**全部实机值**
5. **流程配置**：`#/setting/flow` → 搜索表单名 → 截图列表与设计器（记录 `workKey`、已配置/未配置）
6. **业务配置弹窗**：列表特殊按钮（如「设置 xx 负责人」）→ 截图
7. 写入 Markdown **说明文字正下方**

#### 截图保存示例

```
d:\Obsidian Vault\写发版报告\数智工厂\发版公告\新人事行政管理\截图\{表单名}\{表单名}-列表页.png
```

## 五、操作手册写作规范（核心）

操作手册是 `{表单名}.md` 的**必备章节**，位于 **2.3**，紧接 **2.2 流程图** 之后。

### 5.1 放置位置（强制）

| 位置 | 要求 |
|------|------|
| **2.3 操作手册** | 必须在 **2.2 端到端业务流程图** 正下方 |
| **2.4 审批链条** | 排在 2.3 之后（无审批的表单 2.4 写「无审批说明」） |
| **主路径操作一览** | 放在 2.3 **章末**，作为阶段 0～N 的索引表 |

### 5.2 阶段划分（阶段 0～10）

按实机主路径拆分，可按表单裁剪，但须**覆盖从进入到办结**：

| 阶段 | 标题示例 | 核心内容 |
|------|---------|---------|
| 0 | 操作前准备 | 上游字典/岗位/负责人/流程配置检查表（含责任人） |
| 1 | 进入列表 | 菜单路径、路由核对、列表按钮确认 |
| 2 | 新建单据 | 点「新增」、确认 `pageType`、上游入口（如办理入职） |
| 3 | 填写并保存 | 分区域/标签页填表、**确定/保存/取消**、状态变化 |
| 4 | 提交与审批 | **提交**、待审核分支、工作台待办同意/驳回/撤回 |
| 5～8 | 业务环节 | 按实机状态逐步推进（如初筛→面试→背调；或账号→档案→签字） |
| 9 | 办结 | 最终状态 + 下游流转 + **办结判定** |
| 10 | 辅助操作 | 搜索、导出、导入、删除、上一条/下一条 |

**每个阶段须包含**：

1. **适用说明**（写在 2.3 章首）：如「贵州基地 `hr_recruit` 未配置，提交后直接进入待筛选」
2. **操作表格**，推荐列：
   - `步骤 | 所在界面 | 具体操作 | 预期结果/状态变化`
   - 或：`步骤 | 操作人 | 具体操作 | 状态变化`
3. **关键步骤加粗按钮名**（如 **新增入职**、**保存并提交**、**完善档案**）
4. **阶段内嵌入实机截图**
5. **注意事项**：常见失败原因、必填校验、权限限制

**章末必备**：

- **主路径操作一览表**：阶段 ↔ 关键按钮 ↔ 操作角色 ↔ 目标状态
- **办结判定**（有流程时）：明确何时视为业务办结
- **基地差异说明**（若适用）：未配置审批 vs 已配置审批

### 5.3 与流程图的一致性

- 操作手册每个阶段的**目标状态**必须与 **2.1 实机状态枚举**、**2.2 流程图节点**一致
- 主路径一览表必须能**逐行对照** 2.2 `flowchart TD` 的节点名称
- 禁止出现流程图未定义的状态或跳跃节点

## 七、各章节写作要求

### 7.1 功能业务介绍

- 写清：管什么、上下游表单、列表主要按钮

- 列表页截图放在介绍段落后

### 7.2 业务流程与操作手册

- **2.1** 状态枚举必须来自实机；有审批时分「单据审批 / 业务环节」；列表辅助列（如账号/档案/签字）单独说明
- **2.2** `flowchart TD` 覆盖主入口分支、驳回/撤回、淘汰终态、下游流转
- **2.3** 操作手册（见第五节）
- **2.4** 必须核对 `workKey`、流程设置实机截图；未配置时如实说明
- **2.5** 第二层业务链条（如入职后处理、招聘环节）；无则写数据维护链条或省略
- 审批入口统一写：**工作台 → 我的待办**

### 7.3 权限与角色

- 角色 × 菜单 × 典型操作 × 说明
- 列表操作须来自实机
- 关键配置项（负责人、流程）与角色对照

### 7.4 核心实操场景

- ≥3 个；覆盖主路径成功、驳回/淘汰、特殊入口（扫码/导入/上游带入）
- 格式：`背景` + `步骤|角色|操作|结果` 表出来

### 7.5 业务规则与业务状态

- 规则 **R01** 起连续编号
- **六、业务规则** 与 **七、业务状态** 须与 **2.1** 一致，不得矛盾
