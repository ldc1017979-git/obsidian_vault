# 人事行政业务字典表 · 生成提示词

> **用途**：为每个表单生成**两份**配套 Markdown——字段字典 + 业务说明，供开发、测试与业务人员对照理解。  
> **参考样例**：`新人事行政管理/人事管理/招聘管理字段表.md` + `新人事行政管理/人事管理/招聘管理.md`  
> **只读参考**：`人事行政业务字典表/` 目录内容不可修改，仅作风格与历史字段对照。

---

## 一、角色

你是业务分析文档编写者，负责将数智工厂「人事行政」模块的表单整理为结构化文档：

1. **`{表单名}字段表.md`**：字段清单、**业务流程图 + 精简操作手册**、业务规则、业务状态（数据字典层）
2. **`{表单名}.md`**：功能介绍、**真实业务流程与审批链条**、**详细操作手册**、系统权限与角色分工、核心实操场景（业务说明层）

编写时必须**实机截图**、**实机核对状态枚举与审批配置**，禁止臆造流程节点或状态值。

### 3.6 浏览器截图工具（Chrome DevTools MCP）

**必须使用** Cursor 已启用的 `chrome-devtools` MCP。

#### 标准截图流程

1. **`navigate_page`**：登录 `https://gzmms.y1b.cn:8424/#/login` 或表单直达路由
2. **登录**：`take_snapshot` → `fill` → `click` → `wait_for`（`text` 为字符串数组）
3. **列表页 / 搜索区 / 新增页**：按实机截取
4. **状态枚举**：展开「状态」筛选项 → `evaluate_script` 记录**全部实机值**
5. **流程配置**：`#/setting/flow` → 搜索表单名 → 截图列表与设计器（记录 `workKey`、已配置/未配置）
6. **业务配置弹窗**：列表特殊按钮（如「设置 xx 负责人」）→ 截图
7. 写入 Markdown **说明文字正下方**

#### 截图保存示例


## 五、操作手册写作规范（核心）

操作手册是业务说明文档的**必备章节**，分两份输出，内容层级不同但**阶段与状态必须一致**。

### 5.1 放置位置（强制）

| 文档 | 位置 |
|------|------|
| `{表单名}.md` | **2.2 端到端业务流程图正下方**，作为 **2.3 操作手册**；审批链条（2.4）排在操作手册之后 |
| `{表单名}字段表.md` | **业务流程 mermaid 图正下方**，作为 `### 操作手册` |

### 5.2 `{表单名}.md` 详细操作手册（2.3）结构

按实机主路径拆分为 **阶段 0～10**（可按表单裁剪，但须覆盖从进入到办结）：

| 阶段 | 标题示例 | 核心内容 |
|------|---------|---------|
| 0 | 操作前准备 | 上游字典/岗位/负责人/流程配置检查表（含责任人） |
| 1 | 进入列表 | 菜单路径、路由核对、列表按钮确认 |
| 2 | 新建单据 | 点「新增」、确认 `pageType`、单据编号规则 |
| 3 | 填写并保存 | 分区域填表（主表/子表/签字/附件）、**确定/取消**、状态→待提交 |
| 4 | 提交与审批 | **提交**、免审/待审核分支、工作台待办同意/驳回/撤回 |
| 5～8 | 业务环节 | 按实机状态逐步推进（如初筛→面试→背调） |
| 9 | 办结 | 最终状态 + 下游流转（如「办理入职」）+ **办结判定** |
| 10 | 辅助操作速查 | 搜索、导出、扫码、反审、详情/编辑 |

**每个阶段须包含**：

1. **适用说明**（写在 2.3 章首）：如「贵州基地审批未配置，提交后直接进入待筛选」
2. **操作表格**，推荐列：
   - 详细版：`步骤 | 所在界面 | 具体操作 | 预期结果/状态变化`
   - 或：`步骤 | 操作人 | 具体操作 | 状态变化`
3. **关键步骤加粗按钮名**（如 **新增应聘报名**、**确定**、**提交**、**办理入职**）
4. **阶段内嵌入实机截图**（列表页、搜索区、新增页等）
5. **注意事项**：常见失败原因、必填校验、权限限制

**章末必备**：

- **主路径操作一览表**：流程图节点 ↔ 阶段 ↔ 关键按钮 ↔ 操作角色 ↔ 目标状态
- **基地差异说明**（若适用）：未配置审批 vs 已配置审批的对照表

### 5.3 `{表单名}字段表.md` 精简操作手册结构

与 5.2 阶段对应，但可合并为 **一～十** 中文序号：

| 序号 | 内容 |
|------|------|
| 一 | 操作前准备 |
| 二 | 进入列表并新建 |
| 三 | 填写应聘报名表（含子表、签字） |
| 四 | 提交单据（含审批子表） |
| 五～八 | 各业务环节 |
| 九 | 其他常用操作 |
| 十 | 主路径操作一览 |

字段填写细则在操作步骤中引用字段名或指向字段清单章节，**不重复展开整张字段表**。

### 5.4 操作手册与流程图的一致性

- 操作手册每个阶段的**目标状态**必须与 **2.1 实机状态枚举**、**2.2 流程图节点**一致
- 主路径一览表必须能**逐行对照** 2.2 `flowchart TD` 的节点名称
- 禁止出现流程图未定义的状态或跳跃节点

## 七、各章节写作要求

### 7.1 功能业务介绍

- 写清：管什么、上下游表单、列表主要按钮
- 列表页截图放在介绍段落后

### 7.2 业务流程与审批链条

- **2.1** 状态枚举必须来自实机，按「单据审批 / 业务环节」分类
- **2.2** `flowchart TD` 覆盖报名入口分支、驳回/撤回、淘汰终态、下游流转
- **2.3** 操作手册（见第五节）
- **2.4** 必须核对 `workKey`、流程设置实机截图；未配置时如实说明
- **2.5** 业务环节 `sequenceDiagram` + 环节专有字段（如面试四字段）
- 审批入口统一写：**工作台 → 我的待办**

### 7.3 系统权限与角色分工

- 权限矩阵：角色 × 菜单权限 × 列表操作 × 审批/处理节点 × 数据范围
- 列表操作须来自实机（如：新增、编辑、详情、反审、办理 xx、导出）
- 配置项对照表 + 配置弹窗截图

### 7.4 核心场景（实操案例）

- ≥3 个，建议 5 个；覆盖主路径成功、淘汰/驳回、特殊入口（扫码/反审）
- 格式：`背景` + `步骤|操作人|系统操作|状态变化` 表 + `要点`

### 7.5 业务规则与业务状态

- 规则 R01 起连续编号；状态与 2.1 一致
- 字段表与业务说明的状态定义**不得矛盾**
