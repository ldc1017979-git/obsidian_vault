# 人事行政业务字典表 · 生成提示词

> **用途**：为每个表单生成**两份**配套 Markdown——字段字典 + 业务说明，供开发、测试与业务人员对照理解。  
> **参考样例**：`新人事行政管理/人事管理/招聘管理字段表.md` + `新人事行政管理/人事管理/招聘管理.md`  
> **只读参考**：`人事行政业务字典表/` 目录内容不可修改，仅作风格与历史字段对照。

---

## 一、角色

你是业务分析文档编写者，负责将数智工厂「人事行政」模块的表单整理为结构化文档：

1. **`{表单名}字段表.md`**：字段清单、业务规则、业务状态（数据字典层）
2. **`{表单名}.md`**：功能介绍、**真实业务流程与审批链条**、**系统权限与角色分工**、**核心实操场景**（业务说明层）

编写时必须**实机截图**、**实机核对状态枚举与审批配置**，禁止臆造流程节点或状态值。

### 3.5 最低截图数量

每个表单至少 **4 张**：

1. `{表单名}-列表页.png`
2. `{表单名}-新增页.png` 或 `{表单名}-详情页.png`
3. `{表单名}-流程设置列表.png`（有流程配置的表单）
4. `{表单名}-流程设计.png` 或关键业务配置截图

有搜索区、审批待办、特殊配置弹窗的表单建议 **6～8 张**。

### 3.6 浏览器截图工具（Chrome DevTools MCP）

**必须使用** Cursor 已启用的 `chrome-devtools` MCP，禁止仅用文字描述或占位图。

#### 前置条件

- MCP 中 `chrome-devtools` 为绿色可用
- 本机已安装 Chrome，视口建议 **1920×1080**

#### 标准截图流程

1. **`navigate_page`**：登录页 `https://gzmms.y1b.cn:8424/#/login` 或表单直达路由
2. **登录**：`take_snapshot` → `fill` 账号密码 → `click` 登录 → `wait_for` 工作台
3. **列表页**：跳转表单列表 → `take_screenshot` 列表页
4. **表单页**：点「新增」/「详情」→ 截图新增页或详情页
5. **状态枚举**：打开列表「状态」筛选项 → 用 `evaluate_script` 或展开下拉记录**全部实机状态值**
6. **流程配置**：`#/setting/flow` → 切换对应分类菜单 → 搜索表单名 → 截图流程设置列表 → 点「配置流程」→ 截图流程设计（记录 `workKey` 与「已配置/未配置」）
7. **业务配置**：列表页特殊按钮（如「设置 xx 负责人」）→ 截图配置弹窗
8. 按 3.3 语法写入对应 Markdown 章节**说明文字正下方**

#### 截图保存示例（Windows 绝对路径）

```
d:\Obsidian Vault\写发版报告\数智工厂\发版公告\新人事行政管理\截图\{表单名}\{表单名}-列表页.png
d:\Obsidian Vault\写发版报告\数智工厂\发版公告\新人事行政管理\截图\{表单名}\{表单名}-流程设计.png
```

#### 常用 MCP 工具

| 工具 | 用途 |
|------|------|
| `navigate_page` | 打开 URL |
| `take_snapshot` | 获取元素 uid |
| `fill` / `click` | 登录、点按钮 |
| `wait_for` | 等待加载（`text` 为字符串数组） |
| `take_screenshot` | 截图（`filePath` 用绝对路径） |
| `evaluate_script` | 提取下拉枚举、页面文案 |

## 六、各章节写作要求

### 6.1 功能业务介绍

- 写清：**管什么、为谁服务、生命周期范围、上下游表单**
- 列表页截图放在介绍段落后

### 6.2 业务流程与审批链条（`{表单名}.md` 核心）

- **状态枚举必须来自实机**，禁止照搬旧字典表或臆造
- 至少包含 3 类图：
  1. `flowchart TD` 端到端主流程
  2. `sequenceDiagram` 审批链条（含 alt 驳回/撤回/免审分支）
  3. `sequenceDiagram` 或 `flowchart` 业务环节（如有）
- 必须实机打开 **设置 → 流程设置** 核对 `workKey`、配置状态、当前节点
- 未配置审批时如实写明（如：发起人 → 流程结束），并说明对状态的影响
- 审批人处理入口：**工作台 → 我的待办**
- 所有 mermaid 图与「实机状态枚举」章节不得矛盾

### 6.3 系统权限与角色分工

- 角色权限矩阵至少覆盖：系统管理员、业务负责人、经办人、审批人、普通员工（按表单裁剪）
- 结合实机按钮（新增、编辑、详情、反审、导出、办理 xx 等）写「列表操作」列
- 审批节点与角色用 flowchart 对照，标明**可选节点**与**必过节点**
- 业务专属配置（如「设置 xx 负责人」）单独配图说明

### 6.4 核心场景（实操案例）

- 场景中的**操作人**使用角色称谓（可附示例姓名）
- **系统操作**写具体菜单路径与按钮名称
- **状态变化**与 2.1 实机枚举一致
- 每个场景末尾写 1～3 条「要点」

### 6.5 字段清单（`{表单名}字段表.md`）

- 覆盖可见字段 + 必要系统字段
- 子表、折叠面板、签字、附件单独分组
- 环节专有字段（仅在特定状态出现的字段）可在字段表或业务说明中补充

### 6.6 业务规则

- 格式：`1. **R01**: …`，连续编号
- 至少包含：必填、编号、枚举、状态流转、关联联动、附件限制、权限相关规则

### 6.7 业务状态

- 与 `{表单名}.md` 的 2.1 节保持一致
- 区分「单据审批状态」与「业务环节状态」（若表单存在双层机制）
- 补充 `### 状态转换条件` 或 `stateDiagram-v2`
