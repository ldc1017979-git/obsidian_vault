# 异动管理字段表

## 功能业务介绍
异动管理模块用于记录和管理员工的岗位异动信息，包括异动前信息、异动后信息和系统通用字段，支持异动流程的全生命周期管理，从创建异动到待提交、待审核、申请完成、定岗中、异动完成/异动失败的状态流转，并提供异动失败后返回原岗位的功能。同时支持异动定岗单据关联异动申请单据，实现流程的连贯性和数据的一致性。

## 业务流程
```mermaid
sequenceDiagram
    participant HR as 人力资源
    participant System as 系统
    participant Approver as 审批人
    participant Department as 部门

    HR->>System: 创建异动申请
    System->>System: 生成异动单据
    System->>HR: 确认信息
    HR->>System: 提交异动申请
    System->>System: 状态变更为待提交
    System->>Approver: 通知审批
    Approver->>System: 审核申请
    alt 审核通过
        System->>System: 状态变更为申请完成
        System->>Department: 通知部门
        Department->>System: 启动异动定岗流程
        System->>System: 状态变更为定岗中
        Department->>System: 创建异动定岗单据
        alt 关联异动申请
            Department->>System: 关联异动申请单据
            System->>System: 自动填充相关信息
        end
        alt 定岗成功
            System->>System: 状态变更为异动完成
            System->>HR: 通知异动结果
        else 定岗失败
            System->>System: 状态变更为异动失败
            System->>HR: 通知异动结果
            HR->>System: 返回原岗位
        end
    else 审核不通过
        System->>System: 状态变更为待提交
        System->>HR: 通知审核结果
        HR->>System: 修改异动信息
    end
```

## 业务规则
1. **R01**: 是否关联异动申请、在职员工姓名、工号、单据编号、异动日期、异动类型、异动后部门（数智工厂）、异动后部门、异动后职务、异动后岗位（数智工厂）、异动后部门负责人、计划异动定岗日期、实际异动转定岗日期、主键ID、创建时间、更新时间、创建人、更新人为必填字段
2. **R02**: 异动状态流转规则：待提交→待审核→申请完成→定岗中→异动完成/异动失败
3. **R03**: 审核不通过时，状态返回待提交，可修改后重新提交
4. **R04**: 异动失败时，可返回原岗位
5. **R05**: 异动完成状态由异动定岗状态=已完成后自动变更
6. **R06**: 工作地点支持多选
7. **R07**: 异动定岗附件限制：最多支持 10 个，单文件≤100M，支持格式：jpg、png、gif、jpeg、zip、pdf、rar、docx、doc、xlsx、ppt、pptx、pptm、xls
8. **R08**: 是否关联异动申请枚举值为：1 = 关联，0 = 不关联
9. **R09**: 关联异动申请时，系统自动填充相关信息

## 业务状态
- **待提交**: 初始状态，异动信息已创建但未提交审核
- **待审核**: 异动信息已提交，等待审批人审核
- **申请完成**: 审核通过，异动申请流程完成
- **定岗中**: 正在进行异动定岗流程
- **异动完成**: 定岗成功，异动流程完成
- **异动失败**: 定岗失败，可返回原岗位
