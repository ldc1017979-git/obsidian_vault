# 系统单据字段字典抽取与汇总表标准

适用对象：后续所有系统业务单据字段字典提取、四基地字段对照、统一字段梳理。  
沉淀来源：生产管理 → 灌装 → 灌装工序 字段字典表整理方式。  
核心目标：后续任何单据都必须能按系统详情页逐行核对，不遗漏字段，不乱合并模块，不打乱页面顺序。

## 一、抽取边界

只抽取系统详情页字段，不抽取列表页字段、查询条件、按钮、选项值、标题噪声。

必须抽取：

- 单据详情页 `单据内容` 中所有业务字段。
- 单据详情页 `单据日志` 中实际显示的日志字段。
- 明细表中的列字段，例如：序号、时间、检查人、备注等。
- 签字/确认类字段，例如：当班签字、接班签字、审核签字、化验员等。
- 附件、上传类字段。

不抽取：

- 页面按钮：操作、关闭、创建、删除、编辑、保存等。
- 选项值：合格/不合格、正常/异常、有/无、齐全/不齐全等。
- 页面导航、菜单、账号名、测试账号、系统标题。
- 明细表已有的样例行数据。
- 只有标题意义、不是字段的提示文本，例如 `顶盖版本信息>`。

审批流程、冲销审批流程只有在详情页中存在实际流程字段时才抽取；如果只有空流程或无有效字段，不入表。

## 二、字段归属模块规则

字段必须先归属到系统详情页对应模块，再进入总表。

模块归属优先级：

1. 以系统详情页显示的模块标题为准，例如：基础信息、工序记录、上机顶盖版本信息、工序状况。
2. 同一字段名如果出现在不同模块，不能因为字段名一样就合并到同一模块。
3. 同一字段语义跨基地归属模块不同，必须保留各基地真实模块，并在总表/统一字典中标黄。
4. 系统页面没有明确模块标题、但字段成组出现的，可按字段组建立业务模块，例如：清洁/消毒确认。

示例：

- 广东、贵州的 `顶盖批号` 属于 `上机顶盖版本信息`。
- 湖北、福建的 `顶盖批号` 属于 `原材料使用情况`。
- 这类字段不能强行放到同一个模块下，必须按各基地真实归属保留。

## 三、页面顺序规则

字段顺序必须按系统详情页从上到下排列。

执行要求：

1. 每个基地必须单独保留一张“页面顺序子表”。
2. 页面顺序子表必须严格按该基地系统详情页 DOM/截图从上到下字段顺序排列。
3. 总表按主参考基地页面顺序为主轴，其他基地独有字段按其在本基地系统页面中的位置插入。
4. `单据日志` 排在 `单据内容` 所有模块之后。
5. 不允许用人工主观模块顺序替代系统页面顺序。

推荐主参考基地：

- 当前四基地汇总时，以广东基地为主参考基地。
- 如果后续单据不是广东先提取，可先用首个完整基地作为主参考基地，后续再按用户指定调整。

## 四、总表结构标准

总表不是“每个基地各写一段”的流水账，而是横向核对表。

总表必须满足：

- 同一字段归属模块 + 同一字段语义，一行展示。
- 广东、湖北、江苏、贵州、福建曾用名横向并列。
- 各基地是否适用横向打勾。
- `字段名（新）` 暂不填写，保持空白。
- `统一字段编码` 暂不填写，保持空白。
- 曾用名必须放系统页面原字段名，不能翻译、不能改写、不能自行规范化。

标准列结构：

| 列 | 字段 |
|---|---|
| A | 页面序号 |
| B | 字段名（新），保持空白 |
| C | 数据库字段名称/临时字段编码 |
| D | 字段归属模块 |
| E-I | 各基地曾用名 |
| J | 来源（只针对本单据） |
| K | 类型 |
| L | 是否集团标准字段 |
| M-Q | 各基地适用标记 |

其中：

- `页面序号` 可用基地简称 + 页面序号表示，例如 `粤1/鄂1/黔1/闽1`。
- `数据库字段名称/临时字段编码` 允许作为临时技术标识，但不等于最终统一字段编码。
- 如果同一字段跨模块，临时字段编码必须带模块前缀，避免不同模块字段被误认为同一行。

## 五、页面顺序子表标准

每个基地必须有独立子表，用来回到系统页面逐行核对。

命名方式：

- `单据名_广东页面顺序`
- `单据名_湖北页面顺序`
- `单据名_贵州页面顺序`
- `单据名_福建页面顺序`

子表列结构：

| 列 | 字段 |
|---|---|
| A | 页面序号 |
| B | 字段名（新），保持空白 |
| C | 数据库字段名称/临时字段编码 |
| D | 字段归属模块 |
| E | 曾用名 |
| F | 来源（只针对本单据） |
| G | 类型 |
| H | 是否集团标准字段 |
| I | 是否入统一表 |
| J | 备注 |

子表验收要求：

- 第 1 个字段必须等于系统详情页第 1 个业务字段。
- 每个模块内字段顺序必须与系统页面一致。
- 模块与模块的先后必须与系统页面一致。
- 不允许为了总表好看而改变基地子表原始顺序。

## 六、统一字典表标准

统一字典用于看跨基地差异，不替代总表和页面顺序子表。

统一字典必须展示：

- 广东字段归属模块
- 湖北字段归属模块
- 贵州字段归属模块
- 福建字段归属模块
- 广东曾用名
- 湖北曾用名
- 贵州曾用名
- 福建曾用名
- 来源
- 类型
- 适用基地
- 备注

注意：

- `统一字段编码` 暂不填写。
- 如果同一统一字段在不同基地归属模块不同，备注中要说明“模块不一致，已在总表/页面顺序子表按真实模块保留”。

## 七、颜色规则

颜色只表达核对状态，不表达字段对错。

黄色：

- 同一统一字段跨基地字段归属模块不同。
- 总表中可以在页面序号、数据库字段名称、字段归属模块区域标黄。
- 统一字典中可以在“模块是否一致/各基地模块”区域标黄。

红色：

- 同一模块、同一字段语义下，各基地曾用名不一致。
- 只标红存在差异的曾用名单元格。

不标色：

- 字段缺失不一定标红；缺失通过适用基地空白体现。
- 不同模块下的同名字段，不因为名字一样直接标红合并。

## 八、来源与类型口径

来源只针对当前单据字段录入方式，不是数据系统来源。

推荐来源：

- 自动带入
- 手填
- 选择
- 签字/确认
- 上传
- 系统展示

推荐类型：

- 文本
- 数值
- 日期/时间
- 枚举值
- 人员/签名
- 附件
- 明细项
- 日志信息

如果系统页面无法判断来源/类型，先按页面控件和业务语义判断，后续由业务人员复核。

## 九、禁止事项

禁止以下做法：

- 不登录系统、不看详情页，只根据已有表或字段名猜。
- 使用浏览器翻译后的字段作为曾用名。
- 把列表页字段、筛选项、按钮当成详情页字段。
- 把选项值当字段。
- 把同名字段跨模块强行合并。
- 把模块顺序按主观业务理解重排。
- 把字段顺序按字段编码、拼音、字母或录入顺序排序。
- 擅自填写 `字段名（新）`。
- 擅自填写 `统一字段编码`。
- 只做总表，不做各基地页面顺序子表。

## 十、必做 QA

每个单据交付前必须完成以下检查。

### 1. 文件检查

- xlsx 能正常打开。
- 没有公式错误：`#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
- 主表、统一字典、各基地页面顺序子表都存在。

### 2. 字段来源检查

- 每一个入表曾用名都能在对应基地详情页 DOM 文本或截图中找到。
- 不存在按钮、选项值、账号名、菜单、导航等页面噪声字段。

### 3. 顺序检查

- 每个基地页面顺序子表与该基地系统详情页顺序一致。
- 模块顺序与系统页面一致。
- 模块内字段顺序与系统页面一致。
- `单据日志` 位于 `单据内容` 之后。

### 4. 汇总检查

- 总表为横向核对结构，不是各基地分段流水账。
- 同模块同字段横向并列展示四基地曾用名。
- 跨模块字段没有被强行合并。
- 跨基地模块不一致已标黄。
- 同模块曾用名不一致已标红。
- B 列 `字段名（新）` 保持空白。
- `统一字段编码` 保持空白。

## 十一、交付物清单

每个单据最终至少交付：

1. 字段字典 xlsx。
2. 主表：`单据名`。
3. 统一字典表：`单据名_统一字典`。
4. 各基地页面顺序子表。
5. 审计说明表或 QA 文档。
6. 系统页面 DOM/截图证据。
7. QA 自检记录。

## 十二、给后续执行人的一句话标准

后续任何系统单据字段抽取，都按这个原则执行：

> 先以每个基地系统详情页真实顺序提取字段；再按字段归属模块保留真实结构；最后做四基地横向汇总。总表用于跨基地对照，基地页面顺序子表用于逐行回查系统页面。字段不翻译、不猜、不强行合并，顺序以系统页面为准。
