# 负责人发包与收包说明

## 发包目标

验证V3工作流能否处理产品经理实际收到的全新需求，而不是验证Codex是否记得旧案例。负责人不需要提前知道或指定每个人测试什么；每位产品经理从自己当前工作中选择一个真实全新需求。

## 发给每个人的内容

所有人发送同一个通用V3 ZIP，不附任务答案，不需要负责人逐人分包。通用ZIP解压后固定为：

```text
产品经理工作流V3_新需求验证版/
├── 00-收到后从这里开始.md
├── workflow/
└── 本次任务/
    ├── 01-个人任务卡_请本人填写并重命名.md
    └── 原始资料/
```

产品经理自行选择一个当前真实、且没有使用本工作流处理过的新需求，填写根目录任务卡并重命名为`个人任务卡_姓名_需求名称.md`，把已有资料放入`本次任务/原始资料/`。如果不想手工填卡，可直接执行统一启动指令，由Codex只收集姓名、需求名称、业务原话或资料路径三项最小信息并代为生成。

产品经理在Codex中新建任务时选择整个解压根目录作为当前项目，再执行`workflow/21_新需求验证包/02-统一启动指令-新需求.md`。不要只选择`workflow/`子目录，不要只上传ZIP而不解压，也不要改变`workflow/`内部结构。

个人总结模板和主观反馈表已经在ZIP的`workflow/21_新需求验证包/`内，不需要另外发副本。使用时复制到个人项目输出目录填写，不能直接修改`workflow/`母版。

禁止发：第二轮个人目录、旧PRD、旧HTML、旧问题答案、旧案例专用提示、其他参测人的反馈表。

## 负责人群发前检查

- [ ] 发送的是同一个通用ZIP，包内没有预填姓名、需求名称、任务答案或项目终点。
- [ ] 根目录含本人自填任务卡入口、`本次任务/原始资料/`、统一启动指令、总结和反馈母版。
- [ ] 通知文案明确：产品经理自行选择真实全新需求，不继续使用第二轮旧案例。
- [ ] 通知文案明确：可手工填任务卡，也可由Codex用三项最小信息代为生成。
- [ ] 包内无旧HTML、旧案例答案和案例专用指令。
- [ ] 已用支持UTF-8文件名的ZIP方式打包，中文目录在目标电脑解压后不乱码。
- [ ] 工作流内无负责人电脑或历史项目绝对路径。
- [ ] 个人成果写入独立项目目录，没有直接修改`workflow/`母版模板。
- [ ] Codex当前项目选择的是同时包含`workflow/`和`本次任务/`的根目录，不是单独的`workflow/`。

## 收包必收

| 类别 | 必收文件/证据 |
|---|---|
| 启动 | 个人任务卡、启动冲突表、项目终点、资料审计 |
| 产品过程 | 过程记录、名词表、截图逐元素台账、关键决策与决策预算 |
| 规格 | 当前有效PRD、页面/字段/状态动作契约、AC与追溯 |
| 原型 | 当前有效HTML或明确不适用说明、版本清单、开发备注 |
| QA | 真实交互验收、截图/控制台/脚本证据、未覆盖项 |
| 总结 | 个人项目总结、产品经理主观反馈表 |

负责人使用`05-负责人客观验收与横向汇总表.md`独立核查，不直接复制产品经理的主观总分作为客观结论。

## 收口命名

负责人收回各自项目后再汇总，并分别写五维状态。只有达到产品经理任务卡确认的项目终点，整体项目状态才可PASS；其余阶段PASS只能带维度名称。
