# 产品经理需求输入问题清单：数智工厂 HTML 原型生成

用途：在让 Codex 基于数智工厂系统基准生成 HTML 原型前，由产品经理先补齐业务输入。该清单不绑定某个具体模块，适用于新增模块、旧模块改造、流程页、配置页、报表页、看板页等场景。

## 1. 项目定位

1. 本次是新增模块、旧模块改造，还是独立新产品？
2. 是否必须嵌入现有数智工厂系统壳？
3. 本次 HTML 是开发实现原型、产品评审原型、演示原型，还是视觉验证稿？
4. 是否只做 Web 端？是否需要移动端、小程序端或大屏端？
5. 本次一期范围是什么？
6. 本次明确不做什么？

## 2. 菜单与信息架构

1. 模块归属哪个一级业务域？
2. 模块归属哪个二级业务子域？
3. 完整菜单路径是什么？
4. 哪些页面是左侧菜单可见页面？
5. 哪些页面是从列表进入的隐藏新增页？
6. 哪些页面是隐藏编辑页？
7. 哪些页面是隐藏详情页？
8. 哪些页面是工具页、选择页或辅助页？
9. 如果菜单位置不确定，是否允许 Codex 根据现有系统基准推断？

## 3. 核心业务对象

1. 本模块核心业务对象是什么？
2. 它是单据、记录、工单、配置项、台账、报表，还是看板？
3. 是否有主子表结构？
4. 是否有明细行？
5. 是否需要附件？
6. 是否需要备注？
7. 是否需要操作日志？
8. 是否需要审批流程？
9. 是否需要确认、签名、复核或申诉？
10. 是否有编号规则？

## 4. 页面清单

1. 需要哪些列表页？
2. 需要哪些新增页？
3. 需要哪些编辑页？
4. 需要哪些详情页？
5. 需要哪些配置页？
6. 需要哪些报表或台账页？
7. 需要哪些看板或统计页？
8. 需要哪些审批或待办页面？
9. 需要哪些导入、导出或批量处理页面？
10. 哪些页面必须是独立页面 / Tags-View 页签？
11. 哪些操作可以用弹窗或抽屉？

## 5. 字段与表格

1. 列表筛选字段有哪些？
2. 列表表格列有哪些？
3. 新增表单字段有哪些？
4. 编辑表单字段有哪些？
5. 详情页基础信息字段有哪些？
6. 明细表字段有哪些？
7. 哪些字段必填？
8. 哪些字段只读？
9. 哪些字段自动带出？
10. 哪些字段需要下拉、日期、人员选择、部门选择、文件上传？
11. 是否需要字段校验？校验提示是什么？

## 6. 状态机

1. 这个业务有哪些状态？
2. 每个状态下允许哪些操作？
3. 每个操作由哪个角色执行？
4. 每个操作后进入什么状态？
5. 是否允许保存草稿？
6. 是否允许撤回？
7. 是否允许驳回后编辑重提？
8. 是否允许作废？
9. 是否允许删除？删除条件是什么？
10. 是否有完成态？完成后还能做什么？
11. 是否存在自动流转、超时处理或默认确认？

## 7. 权限与角色

1. 有哪些角色？
2. 每个角色能看到哪些菜单？
3. 每个角色能看到哪些数据范围？
4. 谁可以新增？
5. 谁可以编辑？
6. 谁可以查看详情？
7. 谁可以审批、确认、复核？
8. 谁可以导入、导出？
9. 谁可以删除、撤回、作废？
10. 是否存在本人数据、部门数据、全公司数据等范围差异？

## 8. 审批与流程

1. 是否接入现有流程设置？
2. 是否需要审批流？
3. 审批节点有哪些？
4. 审批人如何确定？
5. 没有配置审批流时如何处理？
6. 审批通过后进入什么状态？
7. 审批驳回后如何处理？
8. 是否需要抄送？
9. 是否进入待办中心？
10. 是否需要审批日志和流程图？

## 9. 批量、导入、导出

1. 是否需要批量新增？
2. 批量新增是一张单据多条明细，还是多张独立单据？
3. 是否需要导入模板？
4. 导入后是否需要校验和错误列表？
5. 是否需要批量审批、批量确认、批量作废？
6. 是否需要导出当前列表？
7. 是否需要异步下载中心？
8. 导出范围是当前筛选结果、选中数据，还是全部数据？

## 10. 弹窗、抽屉与页面边界

1. 新增是否必须是页面？
2. 编辑是否必须是页面？
3. 详情是否必须是页面？
4. 申诉、复核、审批详情是否必须是页面？
5. 哪些轻量操作可以用弹窗？
6. 哪些选择类操作可以用抽屉？
7. 哪些风险操作必须二次确认？
8. 弹窗中是否允许复杂表单？如果不允许，请明确说明。

## 11. 报表、看板与统计

1. 是否需要统计指标？
2. 指标有哪些？
3. 统计维度有哪些？
4. 时间维度是日、月、季度、年度，还是自定义范围？
5. 是否需要趋势图、排行、占比图？
6. 是否需要明细下钻？
7. 是否需要导出统计结果？
8. 看板是否仍保留系统壳？
9. 是否明确需要大屏？如果没有明确要求，默认不做暗黑大屏。

## 12. 数据规则

1. 单号或编号如何生成？
2. 数据是否按部门、基地、产线、仓库、角色隔离？
3. 是否需要历史记录？
4. 是否允许修改历史数据？
5. 是否有年度、月度、班次、批次等周期规则？
6. 是否有清零、归档、结转、冲销等规则？
7. 是否保留历史明细？
8. 是否有外部系统数据来源？

## 13. 风格与体验边界

1. 是否必须完全贴合数智工厂后台风格？
2. 是否允许做轻微视觉优化？
3. 是否禁止营销页、讲解页、演示页？
4. 是否禁止大 hero、深色科技大屏、大面积渐变？
5. 是否需要和现有系统截图保持高度一致？
6. 是否要保留 Tags-View？
7. 是否要保留顶部业务域导航？
8. 是否要保留左侧菜单？

## 14. 禁用词与污染检查

1. 本模块不能出现哪些旧业务词？
2. 是否需要排查采购类污染词？
3. 是否需要排查演示型文案？
4. 是否有明确不属于本模块的功能名？
5. 是否有容易被 Codex 误加的功能？

通用建议排查：

```text
演示|讲解|DEMO|汇报|采购单|供应商|采购部门|采购类型|原料|备件|批量添加|下一步|待入库|结算|反审|上架|下架
```

## 15. 交付与验收

1. HTML 文件名是什么？
2. 输出到哪个目录？
3. 是否需要同时输出过程记录？
4. 是否需要输出交付清单？
5. 是否需要截图？
6. 产品验收重点是什么？
7. 开发验收重点是什么？
8. 必须点击验证哪些核心路径？
9. 哪些问题出现即判定失败？
10. 最终回答是否必须包含读取文件、路径判断、QA 结果和污染词检查结果？

## 16. 最低必填项

如果时间有限，至少必须提供：

1. 项目类型。
2. 菜单路径。
3. 核心业务对象。
4. 页面清单。
5. 状态机。
6. 角色权限。
7. 新增/编辑/详情/弹窗边界。
8. 一期范围和不做范围。
9. 禁用词。
10. HTML 输出文件名。
