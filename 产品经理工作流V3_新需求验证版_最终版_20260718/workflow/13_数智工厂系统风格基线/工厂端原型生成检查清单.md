# 数智工厂工厂端原型生成检查清单

用于后续 Codex 生成或改造工厂端原型前后的验收。只要是承接现有系统，不论新增模块还是改造旧模块，都应逐项检查。

## 测试反馈识别

- [ ] 如果用户提供的是团队测试、产品测试、试跑复盘、测试报告或要求“同步到工作流”，是否先判断这是工作流试跑反馈，而不是普通 HTML 修复。
- [ ] 是否区分问题属于原型缺陷、流程缺陷、强引导缺陷、系统基线缺陷、交互矩阵缺陷、QA 缺陷还是报告结论过满。
- [ ] 是否避免把主路径梳理、交互复核和规则沉淀推回给产品团队。
- [ ] 是否列出需要同步的通用工作流文件和下一轮团队测试口径。
- [ ] 只有用户明确要求“先修原型/页面/HTML”时，是否才进入具体制品修复。

## 项目定位

- [ ] 是否判断本次任务是成熟系统新增模块、旧模块改造、独立新产品，还是固定回归测试。
- [ ] 是否明确本基准只约束系统外壳、组件风格、布局密度、页面层级和交互方式。
- [ ] 是否确认没有把任何历史项目中的业务字段、状态、动作或流程迁移到当前模块。
- [ ] 是否先冻结当前模块的业务硬约束，再开始生成原型。
- [ ] 如果业务逻辑和风格适配冲突，是否以业务逻辑为准。

## 信息架构

- [ ] 是否明确归属一级业务域，例如仓储、生产、质量、设备、安全、人事行政、财务、数据、设置。
- [ ] 是否明确二级业务子域，例如采购管理、库房管理、QC质量控制、能源管理、现场管理等。
- [ ] 是否能写出菜单路径：一级域 > 二级域 > 业务组 > 页面。
- [ ] 新增页面是否有可解释的路由层级，而不是孤立页面。
- [ ] 是否区分可见菜单页与隐藏的新建/详情/工具页。

## 页面类型

- [ ] 是否判断页面属于列表、单据新建、详情、编辑、记录检查、报表统计、基础配置、流程审批、看板、知识文件中的哪一类。
- [ ] 页面骨架是否使用该类型的标准结构。
- [ ] 复杂单据是否用独立路由页，而不是小弹窗。
- [ ] 选择器、批量添加、轻量确认是否才使用弹窗或抽屉。

## 业务逻辑

- [ ] 是否列出当前模块核心业务对象，而不是套用其他模块对象。
- [ ] 是否形成业务对象矩阵：对象名称、来源、字段、生命周期、关联对象、责任角色。
- [ ] 是否形成角色权限矩阵：角色、可见页面、可操作按钮、数据范围、状态限制。
- [ ] 是否形成状态矩阵：状态名称、进入条件、可执行动作、下一状态、异常出口。
- [ ] 是否形成动作矩阵：操作入口、触发条件、执行结果、当前页反馈、返回列表同步、失败提示。
- [ ] 是否列出状态机：当前状态、可执行动作、执行角色、下一状态。
- [ ] 是否明确审批、确认、申诉、撤回、作废、删除等规则。
- [ ] 是否明确新增、编辑、详情、申诉等复杂流程页的打开方式。
- [ ] 列表页是否包含查询、重置、展开、表格、分页和行操作。
- [ ] 单据页是否包含基础信息、明细表格、附件、备注、状态和流程动作。
- [ ] 详情页是否包含基础信息、明细、日志、审批流程或相关记录 Tabs。
- [ ] 流程按钮是否按状态出现，例如提交、撤回、审批、驳回、反审、作废、删除、导出。
- [ ] 按钮是否体现权限控制，不是假设所有人都能操作所有动作。

## 视觉风格

- [ ] 是否保留左侧菜单、顶部业务域导航、Tags-View 和浅灰内容背景。
- [ ] 是否使用 Element Plus 风格的按钮、输入框、选择器、表格、Tabs、分页。
- [ ] 是否维持蓝色主色、绿色新增、黄色编辑、红色危险/错误、灰色普通操作。
- [ ] 是否保持高密度后台工具风，不做营销页、超大 hero、装饰性插画、暗黑科技大屏。
- [ ] 表格、筛选、表单是否紧凑，字号和间距是否接近现有系统。

## 交付验收

- [ ] 是否在原型说明中写清楚菜单层级和页面类型。
- [ ] 是否提供开发备注/逻辑说明/字段说明入口，由开发主动打开查看，且不遮挡主业务流程。
- [ ] 开发备注是否覆盖页面用途、字段解释、状态流转、操作结果、权限差异、数据来源/Mock说明、异常/空态/边界规则和待确认事项。
- [ ] 开发备注是否明确 PRD、字段清单、规则表和页面说明仍为正式源文档，HTML 内说明只做开发走读辅助。
- [ ] 是否包含至少一个正常态、空态、错误/校验态或无权限态。
- [ ] 是否提供关键字段、状态字段、操作列、分页和 Tabs。
- [ ] 是否引用本基准包中的菜单、页面类型或动作字典作为依据。
- [ ] 是否完成核心路径点击 QA，例如新增、保存、提交、详情、编辑、审批、撤回、作废、确认。
- [ ] QA 是否区分页面可打开、数据绑定、状态流转、当前页刷新、返回列表同步、角色权限。
- [ ] 点击不同列表行详情时，详情页是否展示当前行对应数据。
- [ ] 详情页执行确认、撤回、作废、删除等动作后，当前详情页和返回列表后的状态是否同步。
- [ ] 新增态是否为空，编辑态是否回填，详情态是否只读，草稿态是否明确。
- [ ] 筛选、刷新、维度切换是否产生对应数据或状态变化。
- [ ] 不同角色和状态下按钮、数据范围是否符合权限矩阵。
- [ ] 桌面、宽表、弹窗/遮罩、新增空态、员工/用户端入口、移动端或窄屏是否完成可读性检查。
- [ ] 测试报告是否避免把未验证内容写成“核心路径全部通过”“状态更新正确”“可交付开发”。
- [ ] 是否搜索并清理当前模块无关的旧业务术语。
- [ ] 是否清理演示型、讲解型、汇报型文案。
- [ ] 原型改动后，是否同步更新过程记录、交付清单或说明文档。
- [ ] 是否避免保存或展示账号、密码、token 等敏感信息。
