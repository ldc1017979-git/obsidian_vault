# 现有系统链接反推设计规范完整性清单

本文件用于 Codex 在产品经理提供现有系统链接、截图、录屏或测试环境时，反推出可复用的设计规范。它的目标不是评价页面好不好看，而是确保后续 HTML 原型能继承现有系统的真实页面结构、组件、交互和视觉规则。

反推过程中必须同步填写02号过程记录中的“原始截图逐元素台账”。每个筛选、列表列、表单字段、状态标签、行操作、页面入口和返回关系都区分“明确可见/可推断未确认”，不能只写已参考页面。

如果没有完成本清单，不能把反推结果当作最终项目基线，只能输出业务结构稿或待确认原型。

## 1. 反推前必须确认

| 项目 | 必须确认 |
|---|---|
| 承载系统 | 页面最终放在哪个系统 |
| 端口/业务域 | 工厂端 / 供应链 / 市场端 / 跨域协同 / 其他 |
| 规范来源 | 现有系统链接 / 测试环境 / 截图 / 录屏 / 同类页面 |
| 是否已有集成规范 | 有 / 无 / 待确认 |
| 是否需要对比已集成规范 | 是 / 否 |
| 登录与权限 | 只用于读取，不保存账号、密码、token 或真实登录链接 |

## 2. 最少采集页面

Codex 不能只看一个页面就总结系统规范。至少应覆盖下面页面类型；如果缺失，必须说明缺口和影响。

| 页面类型 | 作用 | 缺失影响 |
|---|---|---|
| 工作台/首页/默认进入页 | 判断系统壳、导航、全局布局和整体密度 | 无法判断全局框架 |
| 标准列表页 | 判断筛选区、表格、分页、操作区、状态标签 | 列表类原型容易跑偏 |
| 新增/编辑页 | 判断表单分组、必填、保存、提交、取消、明细表 | 新建流程容易错误使用弹窗 |
| 详情页 | 判断详情分组、Tabs、日志、审批流、附件、返回路径 | 详情结构和返回路径容易缺失 |
| 配置/基础资料页 | 判断轻量配置、启停、编辑、删除、排序 | 配置页容易做成单据页 |
| 报表/看板页 | 判断指标、查询、图表、导出、系统壳保留方式 | 看板容易做成独立大屏 |
| 弹窗/抽屉样例 | 判断轻量操作和复杂流程的边界 | 容易把复杂页面塞进小弹窗 |
| 权限/状态差异样例 | 判断按钮显隐、禁用、状态流转 | 开发实现原型缺权限逻辑 |

## 3. 必须反推的规范内容

### 3.1 系统壳和信息架构

必须输出：

- 顶部导航结构。
- 左侧菜单或侧边导航结构。
- 页签、面包屑、返回路径规则。
- 页面内容区背景和容器规则。
- 菜单层级：一级域、二级域、业务组、页面。
- 可见菜单页和隐藏流程页的关系。
- 页面打开方式：独立页、页签、弹窗、抽屉、新窗口。

### 3.2 页面类型规则

必须区分：

- 列表页。
- 新增页。
- 编辑页。
- 详情页。
- 配置页。
- 报表/统计页。
- 看板页。
- 流程审批页。
- 弹窗/抽屉轻操作。

每类页面必须说明标准结构和典型入口。

### 3.3 组件规则

必须输出：

- 按钮：主按钮、次按钮、新增、编辑、删除、危险、禁用。
- 筛选：字段排列、展开/收起、查询、重置。
- 表格：行高、表头、操作列、状态列、空态、分页。
- 表单：分组、必填、校验、明细表、附件、备注。
- 详情：基础信息、明细、Tabs、日志、审批流、附件。
- 弹窗/抽屉：适用场景、宽度/尺寸、按钮位置、关闭规则。
- Toast/Message/Confirm：成功、失败、二次确认、危险操作。
- 状态标签：颜色、文案、和按钮联动关系。

### 3.4 视觉规则

必须输出：

- 主色、辅助色、成功/警告/危险/信息色。
- 背景色、边框色、文字色。
- 字体和字号层级。
- 间距、圆角、阴影、分割线。
- 内容密度：高密度 / 中密度 / 低密度。
- 图标风格。
- 是否允许大图、插画、渐变、大屏风格。

### 3.5 交互和业务规则

必须输出：

- 新增、编辑、详情、删除、导出、提交、审批、撤回、作废等操作路径。
- 操作后结果：页面跳转、状态变化、列表刷新、Toast、二次确认。
- 状态机：状态、可执行动作、下一状态。
- 权限：菜单权限、按钮权限、数据范围、无权限表现。
- 异常：必填、重复、无权限、网络失败、部分成功、空态。

### 3.6 HTML 原型适配规则

必须输出：

- 新模块应放入哪个系统壳。
- 菜单路径建议。
- 需要生成哪些可见页面。
- 需要生成哪些隐藏新增/编辑/详情页。
- 哪些操作用弹窗，哪些必须用独立页或页签。
- 哪些组件和视觉规则必须继承。
- 哪些内容不能照搬现有页面业务字段。

## 5. 已集成规范与链接反推规范对比

如果系统已有集成规范，同时产品又提供了当前链接或截图，Codex 必须对比：

| 对比项 | 已集成规范 | 当前页面反推 | 结论 |
|---|---|---|---|
| 系统壳 |  |  | 一致 / 不一致 / 待确认 |
| 菜单层级 |  |  | 一致 / 不一致 / 待确认 |
| 组件风格 |  |  | 一致 / 不一致 / 待确认 |
| 视觉规则 |  |  | 一致 / 不一致 / 待确认 |
| 页面打开方式 |  |  | 一致 / 不一致 / 待确认 |
| 权限/状态规则 |  |  | 一致 / 不一致 / 待确认 |

如果出现差异，不能自行选择，必须让产品经理确认采用“已集成规范”“当前页面反推结果”或“混合修正规则”。

## 6. 一票否决

出现以下情况，不能生成最终风格 HTML：

- 未说明设计规范来源。
- 只看单个页面就声称完成系统规范反推。
- 未区分页面明确可见和 Codex 推断。
- 未给产品经理确认反推规范。
- 未确认承载系统。
- 现有系统内建设却没有系统壳、菜单、组件和交互规则。
- 把现有页面的业务字段污染到无关新模块。
- 保存账号、密码、token 或真实登录链接。
