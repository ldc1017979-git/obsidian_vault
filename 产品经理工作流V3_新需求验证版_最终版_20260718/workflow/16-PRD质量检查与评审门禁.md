# PRD质量检查与评审门禁

用途：在PRD完成后、页面说明和HTML原型开始前，检查PRD是否完整、一致、可实现、可测试。未通过本门禁，不得进入原型生成。

## 0. 基本规则

1. PRD质量检查发生在“PRD初稿完成后、产品确认后、原型前”。
2. 检查对象必须是唯一的当前有效PRD版本。
3. Codex先执行自检，产品经理确认业务结论；技术问题转研发确认，不能由Codex擅自确定。
4. 所有问题按P0/P1/P2记录；P0/P1未关闭时不得进入开发实现原型。
5. PRD不能只描述页面，要说明业务对象、规则、状态、权限、异常和验收标准。
6. 复杂项目必须有产品级业务对象关系、规则编号和关键数据/状态推演；数据库级模型只作为研发可选建议。
7. 编码前必须按20号规范完成名词表、截图逐元素台账、页面契约、字段契约和状态动作角色关联影响契约。

### 1.1 PRD类型选择

- 完整版：复杂大功能、多模块、跨系统、状态/权限复杂或需要正式研发测试交付。
- 精简版：小功能迭代、字段调整或局部规则优化，但仍必须保留目标范围、流程规则、关键异常、权限、验收和变更记录。
- 不能以“精简版”为理由删除会影响研发和测试判断的字段、状态、权限、异常或验收标准。

## 2. 目标与范围质量

- [ ] 问题背景是事实描述，不是直接写解决方案。
- [ ] 用户痛点、业务目标和成功指标清楚。
- [ ] 目标用户、使用场景和触发条件清楚。
- [ ] 一期范围、非目标和后续范围明确。
- [ ] 现有系统优化与新增能力边界清楚。
- [ ] 跨系统项目明确主系统、责任边界和数据流向。
- [ ] 需求优先级和上线约束明确。

## 3. 资料与结论可信度

- [ ] 列出资料来源、版本和读取日期。
- [ ] 区分已确认、页面明确可见、Codex推断、待业务确认、待研发确认。
- [ ] 旧PRD、现有页面、业务反馈之间的冲突已登记。
- [ ] 没有把Codex建议写成已确认事实。
- [ ] 没有引用不存在、过期或错误的系统基线。

## 4. 用户、角色与权限

- [ ] 列出所有业务角色及职责。
- [ ] 明确谁发起、谁编辑、谁审批、谁确认、谁查看、谁配置。
- [ ] 菜单权限、数据范围、字段读写和动作权限分开描述。
- [ ] 同一对象不同状态下的角色动作明确。
- [ ] 无权限访问和越权操作的反馈明确。

## 5. 业务对象与数据关系

- [ ] 核心对象、对象标识和生命周期明确。

- [ ] 数据来源、归属系统和同步方向明确。
- [ ] 唯一性、重复、并发和幂等规则明确。

- [ ] 复杂对象关系已使用关系表或可视化图表达；简单需求不强制ER图。

## 8. 页面与交互要求

- [ ] 菜单路径、页面层级、入口和返回路径明确。

- [ ] 搜索、重置、分页、排序、导出和批量操作规则明确。
- [ ] 风险动作的二次确认文案和取消行为明确。
- [ ] 成功、失败、部分失败、空态和加载态明确。
- [ ] 防重复点击、重复提交和并发冲突处理明确。
- [ ] 原型用途和视觉基线来源明确。
- [ ] 查询条件的默认值、必填、校验和重置结果明确。
- [ ] 列表的默认排序、可排序列、分页、每页条数和列对齐/格式化规则明确。
- [ ] 关键控件类型明确，例如单选/多选、日期/日期范围、级联选择；不使用“选择XX”等模糊描述。

- [ ] 评审辅助动作已定义为调试能力，不作为正式业务动作或AC。

## 9. 异常、边界与非功能要求

- [ ] 无数据、无权限、数据失效和状态已变化场景明确。
- [ ] 接口失败、同步失败、超时和重试规则明确。
- [ ] 最小/最大值、长文本、大数据量和宽表场景明确。
- [ ] 性能、响应时间、分页量级和导出量级有要求或明确不适用。
- [ ] 安全、审计日志、隐私、留痕和合规要求明确。
- [ ] 浏览器、设备、分辨率和响应式范围明确。
- [ ] 数据迁移、兼容、灰度、回滚和监控要求明确或标记不适用。
- [ ] 多系统场景明确主数据源、数据归属、冲突处理和业务补偿结果。
- [ ] 同步/异步、幂等、超时、重试和技术补偿方案已转研发确认；产品经理只确认业务后果。

## 9A. 审计与留痕

- [ ] 关键新增、编辑、审批、撤回、作废、删除、配置变更是否需要留痕已明确。

## 11. 内部一致性检查

- [ ] 目标、范围、流程、页面和验收标准互相一致。
- [ ] 字段在列表、新增、编辑、详情和导出之间一致。
- [ ] 状态名称和动作在全文一致。
- [ ] 角色名称和权限口径一致。

## 11A. 主档与附件组织

简单PRD可以全部写在主档；复杂PRD可采用“主档+附件”，但不能因拆附件造成关键规则难以查找。

| 内容 | 简单需求 | 复杂需求 |
|---|---|---|
| 主档 | 目标、范围、流程、规则、权限、异常、验收 | 必须保留结论、范围、核心规则、依赖、风险和验收摘要 |
| 字段/对象附件 | 可合并主档 | 产品级对象关系和字段字典 |
| 权限附件 | 可合并主档 | 角色×页面×动作×数据范围×字段权限 |
| UI交互附件 | 可合并主档 | 页面结构、控件、状态和交互矩阵 |
| API/技术附件 | 不强制 | 由研发维护或确认，PRD只引用结论与业务影响 |
| 规则附件 | 规则少时合并主档 | 规则较多时独立维护R编号清单 |

- [ ] 主档中的规则、附件和追溯矩阵链接有效。
- [ ] 附件版本与主档一致，没有引用旧字段、旧状态或旧权限。

判定规则：

- `PASS`：P0/P1为0，核心业务结论已确认，验收标准可执行，可以进入原型。
- `REVIEW`：只有不阻塞结构确认的P2或明确待确认项，可以进入产品确认原型，但不得进入开发实现原型。
- `FAIL`：存在P0/P1、核心结论冲突或验收标准不可执行，不得进入原型。

本节PASS只代表`PRD质量门禁PASS`，不得简称为内部原型QA、研发准入、真实系统UAT或整体项目PASS。
