# 产品经理工作流 V3：新需求验证版

> 版本：2026-07-18。基于5位工厂端产品经理第二轮真实项目证据升级；用于全新需求，不用于继续复测旧案例。

使用前先完整解压通用ZIP。每位产品经理自行选择一个当前真实、且没有使用本工作流处理过的全新需求，填写根目录`本次任务/`中的自填任务卡并放入已有原始资料；也可以启动后让Codex用三项最小信息代为生成任务卡。在Codex中新建任务时，把同时包含`workflow/`和`本次任务/`的整个解压根目录设为当前项目目录，不要只选择`workflow/`子目录。不要直接在ZIP内使用文件，不要改变包内目录结构。

用途：给产品经理使用 Codex 推进工厂端、供应链、市场端或跨域协同等产品需求，从一句模糊想法开始，逐步完成端口判断、资料审计、需求澄清、产品决策、页面结构确认、系统风格 HTML 原型生成和交付验证。

本工作流的核心不是让产品经理自己填一张很长的专业问卷，而是让 Codex 主动引导产品经理完成判断。产品经理只需要说清楚当前知道的内容、选择更接近的方向、补充必要资料、确认 Codex 整理出的结论。

## 1. 产品经理第一句话

产品经理不知道怎么开始时，只需要对 Codex 说：

```text
我现在要做一个项目，我该怎么开始？
```

Codex 必须自动进入详细引导版，不允许直接要求产品经理先填写完整 PRD、完整字段表或完整权限矩阵。

启动必须按漏斗推进：第一轮只确认“做哪个端口/业务域”，第二轮询问“是否有知识库、现有系统资料、历史资料、设计规范来源或规范文档”，第三轮再判断“需求变化类型”“系统承载关系”和“设计规范采用哪种来源”。不能默认都是工厂端，也不能默认都承载在数智工厂。

## 2. 推荐使用顺序

如果本次是团队测试反馈、产品测试复盘、试跑报告或要求“同步到工作流”，不要按普通项目启动。Codex 必须先执行 `01-Codex自动引导总入口-多端口产品工作流.md` 中的“团队测试反馈识别”，再输出问题归类、需要同步的源文件和下一轮团队测试安排。

产品经理只需要优先看下面的启动与反馈入口；其余文件由Codex按阶段自动读取：

| 顺序 | 文件 | 用途 |
|---:|---|---|
| 1 | `00-给产品经理从这里开始.md` | 告诉产品经理怎么启动 |
| 2 | `01-Codex自动引导总入口-多端口产品工作流.md` | Codex 执行多端口引导和系统基线分流 |
| 3 | `08-端口分流与资料引导卡.md` | 说明不同端口后续如何引导 |
| 4 | `09-现有系统链接反推设计规范完整性清单.md` | 给链接/截图时约束 Codex 必须反推哪些规范 |
| 5 | `10-产品提供规范文档提炼完整性清单.md` | 给 Figma/Axure/蓝湖/组件库等规范文档时约束 Codex 必须提炼哪些规则 |
| 6 | `07-试跑验证反馈表-多端口产品工作流.md` | 试跑后记录问题 |

其余文件由 Codex 自动读取和执行，产品经理不需要一开始全部读完。

## 4. 整合原则

- `产品流程-测试` 的工作流规则作为产品经理协作主干。
- 第一轮先判断端口/业务域：工厂端、供应链、市场端、跨域协同或不确定。
- 第二轮再判断是否有知识库、现有系统资料、历史资料、截图、录屏、旧 PRD、字段表、设计规范来源或规范文档。
- 第三轮才判断需求变化类型、系统承载关系、需要继承的系统基线，以及设计规范采用“已集成规范 / 现有系统链接反推 / 产品提供规范文档 / 暂无”中的哪一种。
- 设计规范来源分四类：工作流已集成规范可直接读取；产品提供现有系统链接/截图时，Codex 必须先反推规范并给产品确认；产品提供 Figma、Axure、蓝湖、组件库、UI 规范或交互规范时，Codex 必须先提炼成项目基线；暂无规范来源时不能生成最终风格 HTML。
- 链接反推规范必须按 `09-现有系统链接反推设计规范完整性清单.md` 执行，不得只看单页就生成最终风格 HTML。
- 产品规范文档必须按 `10-产品提供规范文档提炼完整性清单.md` 执行，不得只把设计稿当视觉参考。
- 包内`13_数智工厂系统风格基线/`只在项目明确承载于数智工厂系统时作为页面、菜单、组件、交互和视觉基准。
- 本包不携带旧案例任务卡、旧答案、旧HTML和案例专用测试指令；系统基线只提供通用规范。
- 启动阶段默认详细引导版，必须使用选择题、解释、推荐理由和影响说明。
- 资料清单是 Codex 背后的检查表，不是产品经理开局要独自填写的作业。

## 5. 新一轮怎么测

负责人从`21_新需求验证包/00-负责人发包与收包说明.md`开始，把同一个通用ZIP发给所有参测产品经理，不预先分配需求。每位产品经理从自己当前工作中选择一个真实全新需求，自行填写任务卡、提供原始资料并确认本轮终点；`workflow/`中保留统一启动指令及反馈/总结母版。

验证重点：Codex能否独立读资料、关闭事实冲突、控制问询成本，在编码前锁定名词和页面/字段/状态契约，并在收口时保持主档同步和五维状态不混称。
