## 4. 错误方向复盘

### 发生了什么

研发准入完成后，Codex在未获得“将终点扩展为真实系统UAT”的明确确认时，直接创建了终点变更记录并进入阶段9。随后围绕部署链接、内部测试和UAT确认人继续收集材料，导致流程偏离用户真正目标“生成新的原型”。

### 为什么是错误

1. “继续”只能表示继续当前任务，不能自动扩大已确认项目终点。
2. 项目终点变化必须由产品经理明确选择并确认，Codex不得从含糊回复推断。
3. 真实系统UAT的前置事实是目标功能已开发并部署；该事实未核验前不得进入阶段9。
4. 环境可访问不等于目标功能已部署，登录页、工作台或其他同类菜单不能作为功能存在证据。

### 造成的影响

- 新增了阶段9准备、UAT记录和环境核验等非目标工作。
- 多轮追问部署证据和访问方式，增加沟通成本。
- 一度将整体项目从已完成的研发准入状态重新置为UAT进行中/REVIEW。
- 没有改写已确认PRD、AC、契约或真实业务数据；错误路径已通过CR-20260723-002关闭。

### 防复发规则

- 用户只说“继续/下一步”时，沿当前已确认终点继续；若终点已达到，先给出下一阶段及前置条件，再要求用户明确确认是否扩展终点。
- 未出现“功能已开发部署”的直接证据，不得创建真实系统UAT执行记录。
- 访问到环境首页或登录成功，只能证明环境可达，不能证明目标功能存在。
- 终点扩展必须单独记录用户原话，不能用Codex解释替代确认。
